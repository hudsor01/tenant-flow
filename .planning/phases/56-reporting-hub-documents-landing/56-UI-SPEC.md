# Phase 56 — UI Design Contract

> Visual and interaction contract for the Reporting Hub & Documents Landing phase. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **This phase is INFORMATION ARCHITECTURE, not new visual language.** Three overlapping surfaces collapse into one `/reports` hub and `/documents` stops being a bare redirect. No new report types, no new charts, no new npm deps, no new registry blocks. Every token below is the real value read from `src/app/globals.css` (`@theme`). Every surface composes primitives already vendored in `src/components/ui/`.
>
> **The design job is composition and hierarchy.** Three problems were deferred to this contract and are solved in §"Design Problem 1/2/3" below. Everything else is inherited: the existing tile pattern (`financials-quick-links.tsx` `QuickLinkCard`), the existing card grid (`report-card-grid.tsx`), the existing paywall rail (`PaywallError` → sonner toast), the existing vault query (`documentSearchQueries.list`).
>
> **Load-bearing inherited rule (D-18):** lease-derived figures are labelled **Scheduled**, ledger figures are **Collected**, and nothing sums them. See §"Inherited Vocabulary Guard" — a live regression risk was found in the merge target and is closed by this contract.

## Design Problem 1 — `/reports` hub index IA (D-01..D-04)

**The page is a navigation-only directory of 13 destinations. It must read as a purposeful hub, not a link dump.**

### Composition

`/reports/page.tsx` is a **Server Component**. Contract, checkable by grep: **no `"use client"`, no React hooks, no `useQuery`, no `fetch`, no `supabase` import.** D-04 is enforced by the file's own imports.

```
<h1> Reports                                          text-2xl / 600
     Every financial statement, analytics view,        text-sm / 400 / muted
     and export in one place.
                                                       ← 32px band gap (space-y-8)
<section aria-labelledby="reports-statements">
  <h2> Statements                                      text-base / 600
       Accounting views of your portfolio for a         text-sm / 400 / muted
       period you choose.
  grid gap-4 sm:grid-cols-2 xl:grid-cols-3  → 5 tiles
</section>
<section aria-labelledby="reports-analytics">   Analytics  → 6 tiles
<section aria-labelledby="reports-exports">     Exports    → 2 tiles
```

### Tile anatomy (uniform across all 13 — uniformity is the design)

Adapt `QuickLinkCard` from `financials-quick-links.tsx` with the `value`/`trend` props **removed** (D-04: no data). Four fixed slots:

1. **Icon medallion** — `size-10 rounded-lg bg-muted flex items-center justify-center`, lucide icon `size-5 text-foreground`, `aria-hidden="true"`. *Neutral, not `bg-primary/10`* — the accent budget is spent elsewhere (see §Color).
2. **Title** — 16px / 600 / `text-foreground`. Report names stay Title Case (they are document names).
3. **Description** — 14px / 400 / `text-muted-foreground`, one line of copy that answers "which one do I want?", never "what is this".
4. **Tier badge** (conditional) — top-right, `Badge variant="outline"` + `Sparkles` `size-3` + label `Growth`. Only on the two entries whose CTA actually hits a gated `reportType` (see §Tier Gate Contract).

Plus the inherited hover affordance: `ArrowRight size-4` top-right, `opacity-0 group-hover:opacity-100`, `aria-hidden="true"`. When a tier badge is present it occupies the top-right and the `ArrowRight` is omitted from that tile (never stack both).

Whole tile is one `<Link>` — `group bg-card border border-border rounded-lg p-5 hover:bg-muted/50 hover:border-primary/30 transition-colors`. **One link per tile, zero nested interactive elements.**

| Group | Title | Route | Icon | Description | Growth badge |
|-------|-------|-------|------|-------------|:---:|

Group order is fixed **Statements → Analytics → Exports** — what happened, why it happened, give me the file.

### States — explicitly none

The hub index has **no empty state, no loading state, no error state, and no skeletons.** It renders static markup with zero data dependencies, so none of those states can occur. Any skeleton, spinner, `Empty` compound, or error boundary added to `/reports/page.tsx` is a D-04 violation and a blocking defect. The only state on the page is `Link` hover/focus.

No entrance animation. `BlurFade` (used on the legacy `/financials` index) is **not** carried over — animating a static directory adds perceived latency to a page whose only job is to get out of the way.

## Design Problem 2 — `/documents` landing composition (D-14..D-17)

**Locked and non-negotiable:** vault entry + lease-template entry + **four separate** printable template cards + a recent-documents list. Six tiles plus a list. The two real problems are (a) six tiles skew weight toward templates when the vault is the primary destination, and (b) the recent list overlaps `/documents/vault` and the two must not visibly disagree.

**Both are solved by one move: the recent-documents list lives INSIDE the vault panel, and the vault panel is a full-width primary band that the templates cannot compete with.**

### Three-band descending-weight ladder

```
BAND 1 — Vault (full width, bg-card, p-6, contains the recent list)
  ┌──────────────────────────────────────────────────────────────────┐
  │ ▣ size-12 bg-primary/10   Document Vault              16px/600   │
  │   FolderArchive text-primary                                     │
  │   Search, filter, and bulk-download every document attached      │
  │   to your properties, leases, tenants, and maintenance requests. │
  │   [ Open the vault ]   ← the ONLY primary Button on the page     │
  │  ─────────────────────────── Separator ───────────────────────── │
  │   Recently added                                    12px/400/mut │
  │   • Lease agreement — Unit 4B          2 days ago                │
  │   • Inspection report — Maple St       5 days ago                │
  │   • … (exactly 5 rows, non-interactive)                          │
  │                                     View all documents →  (link) │
  └──────────────────────────────────────────────────────────────────┘
                                                     32px band gap
BAND 2 — Build a document (full width, one tile)
  ┌──────────────────────────────────────────────────────────────────┐
  │ ▣ size-10 bg-muted  Lease Template Builder            16px/600   │
  │   Draft a lease from your own clauses, branding, and custom      │
  │   fields, then send it for signature.                            │
  └──────────────────────────────────────────────────────────────────┘
                                                     32px band gap
BAND 3 — Printable forms (grid gap-4 sm:grid-cols-2 lg:grid-cols-4)
  ┌────────┐ ┌────────┐ ┌────────┐ ┌────────┐   compact tiles, p-4
  │▣ size-8│ │▣ size-8│ │▣ size-8│ │▣ size-8│   bg-muted medallion
  │Rental  │ │Property│ │Mainten.│ │Tenant  │   16px/600 title
  │Applic. │ │Inspect.│ │Request │ │Notice  │   14px/400 muted desc
  └────────┘ └────────┘ └────────┘ └────────┘
```

**Why this fixes balance (a):** the vault occupies full width, carries a `size-12` primary-tinted medallion, is the page's only filled primary `Button`, and contains live content — roughly half the page's vertical real estate. Below it, six tiles read as **1 + 4** across two labelled bands with progressively smaller medallions (`size-10` → `size-8`) and padding (`p-5` → `p-4`) and neutral `bg-muted` medallions. Tile count is untouched (D-16 satisfied: four separate cards); the hierarchy is carried by size, width, color budget, and content — not by deleting anything.

**Why this fixes overlap (b) — two independent guarantees:**

1. **Semantic:** nesting the list inside the vault panel, under a `Separator`, below the "Open the vault" CTA, makes it read unambiguously as *a preview of what is in the vault* rather than a second, competing document surface. It is subordinate by position, never a sibling band.
2. **Structural — they cannot disagree, by construction:** the list calls `documentSearchQueries.list({ page: 0 })` from `#hooks/api/query-keys/document-search-keys` with **no filters** and slices the result to the first 5 client-side. That is the exact factory the vault client calls (`documents-vault.client.tsx:230`) → the same `search_documents` RPC → the same `mapDocumentRow` boundary mapper → the same TanStack Query cache entry (unfiltered page 0). The RPC's unfiltered ordering is `d.created_at desc` (verified: `20260426043911_v25_phase_63_search_documents_filter_extension.sql:108`), so "recent" is exactly the vault's own first rows. **Building a second query, a second mapper, or a direct `.from('documents')` select is a blocking violation of this contract.**

### Recent-document row anatomy

`<ul>` of `Item` compound rows, `variant="default"`, `size="sm"`, **non-interactive** — no `<a>`, no `<button>`, no `cursor-pointer`, no hover background. They are a preview, not a control surface.

| Slot | Primitive | Spec |
|------|-----------|------|
| Icon | `ItemMedia variant="icon"` | lucide `File` (or a mime-derived icon if one already exists in the vault client — reuse, do not invent), `size-4 text-muted-foreground`, `aria-hidden="true"` |
| Title | `ItemTitle` | 14px / **400** / `text-foreground`, `truncate`. Override the primitive's default `font-medium` with `font-normal` (see §Typography — two weights only). |
| Meta | `ItemDescription` | 12px / 400 / `text-muted-foreground` — `{document category} · {relative date}` |

**Why rows are not links:** a row that opens a signed URL would be a second download path competing with the vault's — the exact disagreement D-14 warns about — and would require a second signed-URL generation path. One door: the panel's `View all documents` link → `/documents/vault`. `/documents/vault` stays canonical (D-15).

### Recent-list states (this is where states DO exist)

| State | Treatment |
|-------|-----------|
| Loading | 5 `Skeleton` rows at `h-10 rounded-md`, `space-y-2`. Never a spinner. The vault CTA above renders immediately and is never blocked by the list. |
| Empty | `Empty` compound in compact form — `<Empty className="py-6">` with `EmptyTitle` + `EmptyDescription`, **no `EmptyMedia`**. Precedent: `revenue-expense-chart.tsx` already uses `<Empty className="py-12">` for a panel sub-region. No CTA (the vault CTA is 24px above it). |
| Error | Inline `text-sm text-muted-foreground` copy + `Button variant="ghost" size="sm"` labelled `Retry`. Never a raw PostgREST string — route through `handlePostgrestError`. Never an error boundary that takes down the vault CTA. |

### Page-level contract

- `src/app/(owner)/documents/page.tsx` is a **Server Component**; only the recent-documents panel is a `'use client'` island. Server-rendering the list would create a second fetch path and forfeit guarantee (b).
- The file carries a short comment recording that **DOCS-01 superseded** the earlier `permanentRedirect("/documents/vault")` decision and why, so the reversal reads as deliberate (D-17).
- Band headings are real `<h2>`; each band is `<section aria-labelledby>`. Band 1's heading is the vault title itself.
- Every tile is one `<Link>`, whole-card clickable, no nested interactive elements. Medallion icons and the `ArrowRight` are `aria-hidden="true"`.

### Icons — the four printables must be visually distinct

All four template pages currently use `FileText`, which is flat. The landing differentiates them:

| Tile | Route | lucide icon | Description |
|------|-------|-------------|-------------|
| Document Vault | `/documents/vault` | `FolderArchive` (matches nav) | Search, filter, and bulk-download every document attached to your properties, leases, tenants, and maintenance requests. |
| Lease Template Builder | `/documents/lease-template` | `FileCheck` (matches nav) | Draft a lease from your own clauses, branding, and custom fields, then send it for signature. |
| Rental Application | `/documents/templates/rental-application` | `ClipboardList` | Collect applicant details and background-check authorization. |
| Property Inspection | `/documents/templates/property-inspection` | `ClipboardCheck` | Record move-in and move-out condition with checklists and photos. |
| Maintenance Request | `/documents/templates/maintenance-request` | `Wrench` | Issue a work order for a vendor or tenant. |
| Tenant Notice | `/documents/templates/tenant-notice` | `FileWarning` | Late rent, lease violation, and move-out notices. |

## Design Problem 3 — Two nav entries into one hub (D-07)

**Both `Reports → /reports` and `Analytics → /reports/analytics` point into the same hub. They must read as distinct and intentional, and exactly one may be active at a time.**

### Nav shape after consolidation

The `analyticsItems` group in `src/components/shell/main-nav.tsx` drops from three sections to two. The `Financials` section is removed entirely — its identity is absorbed by `Reports`, its children move there.

| Order | Label | href | Icon | Children |
|-------|-------|------|------|----------|
| 1 | Reports | `/reports` | `FileText` | Income Statement, Cash Flow, Balance Sheet, Expenses, Tax Documents, Generate Reports, Year-End |
| 2 | Analytics | `/reports/analytics` | `BarChart3` | Overview, Property Performance |

Also changed: core nav `Documents` retargets `/documents/vault` → **`/documents`**; the one-item `Templates` section is removed (see Discretion table).

**Zero-overlap invariant (checkable):** no `href` appears under both entries. `Financial` is deliberately absent from the Analytics children because `/reports/analytics` **is** the merged Financial view (D-06) — listing it as a child of itself is the duplication this problem is about. The existing curation comment at `main-nav.tsx:65` (Leases / Maintenance / Occupancy reachable as Insights tabs on their own pages) survives unchanged.

### Active-state rule — longest-prefix-wins, exactly one winner

`main-nav.tsx:188` currently computes `pathname.startsWith(href)` per item in isolation. With two nested hrefs that makes **both** entries active on `/reports/analytics/*`. Replace it with a resolver that picks the single best match across the whole nav item set:

> An entry is active **iff** `pathname === href` or `pathname` starts with `href + "/"`, **and** no other nav entry with a longer matching `href` also qualifies.

| Pathname | Reports | Analytics | Documents |
|----------|:---:|:---:|:---:|
| `/reports` | **active** | — | — |
| `/reports/cash-flow` | **active** | — | — |
| `/reports/analytics` | — | **active** | — |
| `/reports/analytics/occupancy` | — | **active** | — |
| `/documents` | — | — | **active** |
| `/documents/vault` | — | — | **active** |

Pin all six cases in `src/components/shell/__tests__/main-nav.test.tsx`. The `aria-current="page"` attribute follows the same single-winner rule — two `aria-current="page"` entries in one nav is an accessibility defect, not just a visual one.

Note the resolver also fixes a latent bug in the current implementation: `startsWith` matches `/reports` against a hypothetical `/reports-archive`. Requiring `pathname === href || pathname.startsWith(href + "/")` closes it.

### Why they read as distinct rather than duplicated — three signals

1. **Distinct icons, distinct semantics.** `FileText` for Reports (documents you produce) vs `BarChart3` for Analytics (charts you read). Already distinct today; preserved.
2. **Distinct, non-overlapping child sets.** A user expanding either entry sees a different, complete list. Nothing appears twice.
3. **The breadcrumb carries the hierarchy the sidebar deliberately hides.** On `/reports/analytics/occupancy` the app-shell breadcrumb renders `Reports / Analytics / Occupancy` — the shared root is visible exactly where hierarchy belongs. The sidebar answers "which menu item am I in" (one answer); the breadcrumb answers "where am I in the tree" (shows both). This division is the resolution, and it requires no new component — `generateBreadcrumbs` already derives from the pathname.

### Breadcrumb label map — required additions

`src/lib/breadcrumbs.ts` `LABEL_MAP` must gain the segments this phase introduces, or the breadcrumb falls back to naive capitalization (`Year-end`, `Tenant-notice`):

| Segment | Label |
|---------|-------|
| `expenses` | Expenses |
| `year-end` | Year-End |
| `vault` | Vault |
| `templates` | Templates |
| `rental-application` | Rental Application |
| `property-inspection` | Property Inspection |
| `maintenance-request` | Maintenance Request |
| `tenant-notice` | Tenant Notice |

And **remove** the now-dead `financials: "Financials"` entry (its route tree is deleted). `analytics`, `financial`, `reports`, `overview`, `property-performance`, `occupancy`, `income-statement`, `cash-flow`, `balance-sheet`, `tax-documents`, `generate`, `documents`, `lease-template`, `leases`, `maintenance` already exist and work correctly as mid-path segments under `/reports`.

The app-shell breadcrumb `<nav>` already carries `aria-label="Breadcrumb"` (`app-shell-header.tsx:54`) — unchanged.

### Roadmap-wording reconciliation (read this before verifying SC-1)

ROADMAP Phase 56 success criterion 1 and RPTHUB-01 both say **"a single navigation entry."** D-07 deliberately keeps **two**. This divergence is user-approved, not a miss. The reconciliation: **the URL space consolidates to one hub (`/reports/*`), while the sidebar keeps two labelled doors into it.** The verifier should read SC-1 as satisfied when every legacy URL lives under `/reports/*` and no third nav section (`Financials`) survives.

## Tier Gate Contract (RPTHUB-03, D-12/D-13)

**How a tier-gated export reads to a free-tier owner: visible, labelled, never disabled, never hidden.**

| Aspect | Contract |
|--------|----------|
| Affordance | Every hub entry and every export CTA renders **identically for all tiers** — same enabled state, same styling, same route. |
| Label | Premium entries carry a static `Badge variant="outline"` with `Sparkles size-3` + text `Growth`, positioned top-right of the tile. It is a **plan label**, not a lock. |
| Icon | **Never `Lock`.** A lock icon reads as denial to a Growth/Max owner who already has the feature. `Sparkles` reads as "this is part of Growth" to everyone. |
| Color | `variant="outline"` neutral only. Never `destructive`, `warning`, or a vivid semantic tint — being on a lower plan is not an error state. |
| Data source | A static frontend constant (`PREMIUM_REPORT_SLUGS`) mirroring the edge functions' `PREMIUM_REPORT_TYPES`. **No subscription fetch on the hub index** — D-04 forbids data fetching there, so the index cannot and must not know the viewer's tier. |
| Enforcement | The Edge Function 402 remains the **sole** gate. `export-report/index.ts:24` (checked :72) and `generate-pdf/index.ts:31` (checked :322). No client-side disable, no route guard, no proxy change (D-13). |
| Free-tier click | The existing rail fires unchanged: `PaywallError` (`report-keys.ts:148`) → sonner toast titled **"Upgrade required"**, description from the edge function (default *"This feature requires a Growth or Max subscription."*), action **"See plans"** → `upgrade_url` (`/billing/plans?source=reports_gate`). **The hub must not introduce a second paywall pattern.** |

### Which entries actually carry the badge — evidence-based, not guessed

Only surfaces whose CTA provably reaches a gated `reportType`:

| Surface | CTA | Edge call | `reportType` | Gated | Badge |
|---------|-----|-----------|--------------|:---:|:---:|
| `/reports/year-end` | Download PDF | `generate-pdf` | `year-end` | yes | **yes** |
| `/reports/tax-documents` | Download PDF | `generate-pdf` | `financial` | yes | **yes** |
| `/reports/generate` | PDF / Excel buttons | none — client-side `jspdf` + `sheetjs` | n/a | **no** | **no** |
| `/reports/year-end` | Year-End CSV, 1099 CSV | none — client-side `downloadCsv()` | n/a | **no** | **no** |
| `/reports/income-statement`, `/reports/cash-flow` | (pages, no export CTA) | none | n/a | n/a | **no** |

`income-statement` and `cash-flow` appear in `PREMIUM_REPORT_TYPES` only as `export-report?type=` query values that no UI currently sends. Badging those tiles would be a false claim about what is gated. Do not badge them.

**Recorded, out of scope:** `reportMutations.downloadYearEndCsv` and `download1099Csv` (`report-keys.ts:267,275`) call the gated `export-report` function but are wired to no UI — the year-end page does client-side CSV instead. ## Typography

Font family `--font-sans` throughout. **Exactly two weights carry all semantics: 400 regular and 600 semibold.** Exactly four sizes cover every surface this phase builds.

| Role | Size | Weight | Line height | Applied to |
|------|------|--------|-------------|-----------|

**Two-weight discipline — three explicit overrides required.** The adapted patterns default to weight 500 (`font-medium`), which would introduce a third weight:

## Color

Tokens are oklch CSS custom properties in `globals.css`, defined in both light and dark. **Never hard-code hex or oklch in components** (see Inherited Vocabulary Guard item 5 for the one existing violation this phase inherits and fixes). No gradient text — globally forbidden. Muted text is `text-muted-foreground`, never bare `text-muted`. Surfaces are `bg-card` / `bg-background`, never `bg-white`.

| Role | Token | Usage |
|------|-------|-------|
| Dominant (60%) | `--color-background` (`bg-background`) | Page canvas on both `/reports` and `/documents` |
| Secondary (30%) | `--color-card` (`bg-card`) + `--color-muted` (`bg-muted`) | Every tile and panel surface; every neutral icon medallion; tile hover `bg-muted/50` |
| Accent (10%) | `--color-primary` / `--color-primary-text` | See the reserved-for list below — five items, nothing else |
| Destructive | — | **Unused. This phase has zero destructive actions.** |

**Accent (primary) reserved for — explicit list, nothing else:**

1. The **vault medallion only** — `bg-primary/10` with a `text-primary` glyph. The single accent-tinted medallion on the documents landing, and the reason the vault reads as primary.
2. The **single primary `Button`** — `Open the vault` (`Button` default variant = `bg-primary text-primary-foreground`). It is the only filled primary button across both new surfaces.
3. **Text link affordances** — `View all documents` (`text-primary-text hover:underline underline-offset-4`), matching the established `usage-section.tsx` upgrade-link treatment.
4. **Hover state on tiles** — border `border-border` → `border-primary/30`, and the `ArrowRight` glyph `text-muted-foreground` → `text-primary-text`. Interaction only, never at rest.
5. **Active nav entry + global focus ring** — both already primary-tinted (`bg-primary/10 text-primary-text`, `--color-ring`). Unchanged.

**Accent is explicitly NOT applied to:** the 13 hub-tile medallions (neutral `bg-muted` + `text-foreground`), the lease-builder or printable-template medallions (neutral), tile titles or descriptions at rest, section headings, the `Growth` tier badge, or recent-document rows. The `/reports` hub index therefore spends accent on nothing but focus rings and hover — correct for a page whose only job is navigation.

**WCAG companion-token rule (CLAUDE.md):** vivid tokens are for icon fills, `-text` companions are for text. This phase uses `text-primary-text` for every accent-coloured *text* run and `text-primary` only for the vault medallion *glyph* sitting on `bg-primary/10`. No `text-destructive`, `text-success`, `text-warning`, or `text-info` appears on either new surface.
