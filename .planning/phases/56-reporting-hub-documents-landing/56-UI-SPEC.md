# Phase 56 — UI Design Contract

> Visual and interaction contract for the Reporting Hub phase. Generated by gsd-ui-researcher, verified by gsd-ui-checker, then **revised post-approval** — see §"Post-approval revision" immediately below.
>
> **This phase is INFORMATION ARCHITECTURE, not new visual language.** Three financial surfaces — `/financials/*`, `/analytics/financial`, and `/reports/*` — collapse into one `/reports` hub. **`/analytics` and its six operational views do not move.** Reports is *financial statements and exports*; Analytics is *operational insight*. Two product surfaces, two sections, one hub each. No new report types, no new charts, no new npm deps, no new registry blocks. Every token below is the real value read from `src/app/globals.css` (`@theme`). Every surface composes primitives already vendored in `src/components/ui/`.
>
> **The design job is composition and hierarchy.** Two problems are solved in §"Design Problem 1" and §"Design Problem 3" below. **Design Problem 2 (the `/documents` landing) has MOVED to Phase 65** and is preserved verbatim in §"MOVED TO PHASE 65" at the end of this document. Everything else is inherited: the existing tile pattern (`financials-quick-links.tsx` `QuickLinkCard`), the existing card grid (`report-card-grid.tsx`), the existing paywall rail (`PaywallError` → sonner toast).
>
> **Load-bearing inherited rule (D-18):** lease-derived figures are labelled **Scheduled**, ledger figures are **Collected**, and nothing sums them. See §"Inherited Vocabulary Guard" — a live regression risk was found in the merge target and is closed by this contract.

## Design Problem 1 — `/reports` hub index IA (D-01..D-04)

**The page is a navigation-only directory of 8 destinations. It must read as a purposeful hub, not a link dump.**

> **REVISED post-approval: 13 → 8.** The original directory carried five `/reports/analytics/*` sub-tiles (Overview, Property Performance, Occupancy, Leases, Maintenance). D-05 is reverted — those five views never move — so listing them here would rebuild inside the hub exactly the cross-section overlap this phase exists to remove. They stay in the `/analytics` section and are **deliberately absent** from the hub.

### Composition

`/reports/page.tsx` is a **Server Component**. Contract, checkable by grep: **no `"use client"`, no React hooks, no `useQuery`, no `fetch`, no `supabase` import.** D-04 is enforced by the file's own imports.

```
<h1> Reports                                          text-2xl / 600
     Every financial statement, analytics view,        text-sm / 400 / muted
     and export in one place.
                                                       ← 32px band gap (space-y-8)
<section aria-labelledby="reports-statements">
  <h2> Statements                                      text-base / 600
       Accounting views of your portfolio for a         text-sm / 400 / muted
       period you choose.
  grid gap-4 sm:grid-cols-2 xl:grid-cols-3  → 5 tiles
</section>
<section aria-labelledby="reports-analytics">   Analytics  → 1 tile
<section aria-labelledby="reports-exports">     Exports    → 2 tiles
```

The grid classes are identical across all three groups. A one-tile Analytics group therefore renders one tile at column width, aligned with the group above it — not a stretched full-width slab. Uniform grid, variable fill.

### Tile anatomy (uniform across all 8 — uniformity is the design)

Adapt `QuickLinkCard` from `financials-quick-links.tsx` with the `value`/`trend` props **removed** (D-04: no data). Four fixed slots:

1. **Icon medallion** — `size-10 rounded-lg bg-muted flex items-center justify-center`, lucide icon `size-5 text-foreground`, `aria-hidden="true"`. *Neutral, not `bg-primary/10`* — the accent budget is spent elsewhere (see §Color).
2. **Title** — 16px / 600 / `text-foreground`. Report names stay Title Case (they are document names).
3. **Description** — 14px / 400 / `text-muted-foreground`, one line of copy that answers "which one do I want?", never "what is this".
4. **Tier badge** (conditional) — top-right, `Badge variant="outline"` + `Sparkles` `size-3` + label `Growth`. Only on the two entries whose CTA actually hits a gated `reportType` (see §Tier Gate Contract).

Plus the inherited hover affordance: `ArrowRight size-4` top-right, `opacity-0 group-hover:opacity-100`, `aria-hidden="true"`. When a tier badge is present it occupies the top-right and the `ArrowRight` is omitted from that tile (never stack both).

Whole tile is one `<Link>` — `group bg-card border border-border rounded-lg p-5 hover:bg-muted/50 hover:border-primary/30 transition-colors`. **One link per tile, zero nested interactive elements.**

### The 8 entries

| Group | Title | Route | Icon | Description | Growth badge |
|-------|-------|-------|------|-------------|:---:|
| Statements | Income Statement | `/reports/income-statement` | `FileText` | What came in, what went out, and what's left for a period. | — |
| Statements | Cash Flow | `/reports/cash-flow` | `TrendingUp` | Money movement month over month, with running balances. | — |
| Statements | Balance Sheet | `/reports/balance-sheet` | `Building2` | A point-in-time snapshot of assets, liabilities, and equity. | — |
| Statements | Expenses | `/reports/expenses` | `Receipt` | Every operating and maintenance cost, by category and property. | — |
| Statements | Tax Documents | `/reports/tax-documents` | `FileSpreadsheet` | Year-end forms and schedules ready for your accountant. | **yes** |
| Analytics | Financial | `/reports/analytics` | `BarChart3` | Scheduled vs Collected rent, expenses, and profitability trends. | — |
| Exports | Generate Reports | `/reports/generate` | `Download` | Build a PDF or Excel report from a date range. | — |
| Exports | Year-End | `/reports/year-end` | `CalendarRange` | Annual income, expenses, and 1099-NEC vendor data. | **yes** |

**Struck by the post-approval revision (do not render, do not link, do not redirect):** Overview, Property Performance, Occupancy, Leases, and Maintenance. Those five keep their existing `/analytics/*` URLs and belong to the Analytics section — see Design Problem 3.

Section one-liners: **Statements** — "Accounting views of your portfolio for a period you choose." **Analytics** — "Charts and trends that explain what the statements show." **Exports** — "Produce a file to hand to your accountant, lender, or partner."

Group order is fixed **Statements → Analytics → Exports** — what happened, why it happened, give me the file.

**Why the Analytics group survives with one tile.** D-02 (the Statements / Analytics / Exports grouping) stands. The group holds exactly one tile because exactly one analytics view — the financial one — is a reporting concern and folds into the hub (D-06). The group heading and one-liner still earn their place: they tell the owner *why* a chart-shaped destination sits among accounting statements, and they mark the boundary between the two sections. Collapsing the tile into Statements would file a trend view as a statement; deleting the heading would leave it unexplained.

### The D-20 Accounts Receivable card is not a hub tile

D-20 ports Accounts Receivable rather than dropping it — it is the one figure that disappears when `/financials` is deleted. It is a **data card, not a navigation tile**, so it cannot live on the hub index: D-04 makes `/reports/page.tsx` a zero-fetch Server Component and that is grep-enforced. It lands on **`/reports/analytics`**, the same surface this contract already names as the surviving home for `/financials`' summary-stat figures (see the `/financials` redirect-target row in the Discretion table). It is therefore governed by the Inherited Vocabulary Guard below, not by the tile anatomy above, and it does **not** change the count of 8.

### States — explicitly none

The hub index has **no empty state, no loading state, no error state, and no skeletons.** It renders static markup with zero data dependencies, so none of those states can occur. Any skeleton, spinner, `Empty` compound, or error boundary added to `/reports/page.tsx` is a D-04 violation and a blocking defect. The only state on the page is `Link` hover/focus.

No entrance animation. `BlurFade` (used on the legacy `/financials` index) is **not** carried over — animating a static directory adds perceived latency to a page whose only job is to get out of the way.

## Design Problem 3 — Reports and Analytics as two real sections (D-07 REVISED)

> **REVISED post-approval. This supersedes the original framing, "Two nav entries into one hub."** That framing followed from D-05 (absorb all of `/analytics/*`) and D-07 (both nav hrefs point into `/reports`). D-05 is reverted and D-07 is revised: the nav carries **`Reports → /reports`** and **`Analytics → /analytics`** — two entries pointing at two different, non-overlapping route trees.

**Reports is financial statements and exports. Analytics is operational insight. They must read as two distinct product surfaces, because they are.** The original problem — two entries competing to be active on one shared prefix — no longer exists; see the active-state section below.

### Nav shape after consolidation

The `analyticsItems` group in `src/components/shell/main-nav.tsx` drops from three sections to two. The `Financials` section is removed entirely — its identity is absorbed by `Reports`, its children move there. **`Analytics` keeps its own href and its own route tree.**

| Order | Label | href | Icon | Children |
|-------|-------|------|------|----------|
| 1 | Reports | `/reports` | `FileText` | Income Statement, Cash Flow, Balance Sheet, Expenses, Tax Documents, Generate Reports, Year-End |
| 2 | Analytics | `/analytics` | `BarChart3` | Overview, Property Performance |

The only change to the `Analytics` entry is that its **`Financial` child is removed** — `/analytics/financial` is the one route that folds into the hub (D-06), and its content now lives at `/reports/analytics`. Owners reach it from the hub's Analytics tile and from the cross-link on the surviving `/analytics` index (D-08 revised). Its href, its icon, and its two remaining children are untouched.

**Not changed by this phase (moved to 65):** the core nav `Documents` entry keeps its current `/documents/vault` target, and the one-item `Templates` section stays. Both were consequences of DOCS-01.

**Zero-overlap invariant (checkable, and now trivially true):** no `href` appears under both entries, and `/reports` and `/analytics` share no path prefix at all. `Financial` is deliberately absent from the Analytics children because `/reports/analytics` **is** the merged Financial view (D-06) and belongs to the Reports tree. The existing curation comment at `main-nav.tsx:65` (Leases / Maintenance / Occupancy reachable as Insights tabs on their own pages) survives unchanged — and so do those `/analytics/*` routes themselves.

### Active-state rule — unchanged, and deliberately so

> **DELETED post-approval: the longest-prefix-wins resolver and its six pinned test cases.**

The original contract required rewriting `main-nav.tsx`'s `isActive` (declared `:188`, `startsWith` call `:190`) because D-07 pointed **both** nav hrefs into `/reports`, which made `Reports` and `Analytics` simultaneously active on `/reports/analytics/*` and emitted two `aria-current="page"` attributes in one nav.

With `Reports → /reports` and `Analytics → /analytics` there is **no prefix overlap**, so the existing per-item `pathname.startsWith(href)` already resolves exactly one winner on every route in scope. The defect dissolved along with its cause. **`main-nav.tsx`'s active-state logic is not modified in this phase, and no new `main-nav.test.tsx` active-state cases are required.**

The `startsWith` hazard against a hypothetical sibling route such as `/reports-archive` is a **latent, unexercised bug** — no such route exists, and none is created here. It is explicitly **out of scope**: do not carry it forward as a drive-by fix.

### Why they read as distinct — three signals

1. **Distinct icons, distinct semantics.** `FileText` for Reports (documents you produce) vs `BarChart3` for Analytics (charts you read). Already distinct today; preserved.
2. **Distinct, non-overlapping route trees.** Not just distinct child lists — distinct URL namespaces. A user expanding either entry sees a different, complete list, and the address bar tells them which section they are in.
3. **The breadcrumb still carries hierarchy inside each section.** On `/reports/analytics` the app-shell breadcrumb renders `Reports / Analytics`; on `/analytics/occupancy` it renders `Analytics / Occupancy`. No new component — `generateBreadcrumbs` already derives from the pathname.

### Breadcrumb label map — required additions

`src/lib/breadcrumbs.ts` `LABEL_MAP` must gain the segments this phase introduces, or the breadcrumb falls back to naive capitalization (`Year-end`):

| Segment | Label |
|---------|-------|
| `expenses` | Expenses |
| `year-end` | Year-End |

And **remove** the now-dead `financials: "Financials"` entry (its route tree is deleted). `analytics`, `reports`, `income-statement`, `cash-flow`, `balance-sheet`, `tax-documents`, `generate` already exist and work correctly as segments under `/reports`; `overview`, `property-performance`, `occupancy`, `leases`, `maintenance`, and `financial` already exist and keep working exactly where they are, under `/analytics`. **`financial: "Financial"` is retained** — nothing in this phase requires its removal, and removing it is out of scope.

**Moved to 65:** the `vault`, `templates`, `rental-application`, `property-inspection`, `maintenance-request`, and `tenant-notice` label-map additions. They belong to the documents landing.

The app-shell breadcrumb `<nav>` already carries `aria-label="Breadcrumb"` (`app-shell-header.tsx:54`) — unchanged.

## Tier Gate Contract (RPTHUB-03, D-12/D-13)

**How a tier-gated export reads to a free-tier owner: visible, labelled, never disabled, never hidden.**

| Aspect | Contract |
|--------|----------|
| Affordance | Every hub entry and every export CTA renders **identically for all tiers** — same enabled state, same styling, same route. |
| Label | Premium entries carry a static `Badge variant="outline"` with `Sparkles size-3` + text `Growth`, positioned top-right of the tile. It is a **plan label**, not a lock. |
| Icon | **Never `Lock`.** A lock icon reads as denial to a Growth/Max owner who already has the feature. `Sparkles` reads as "this is part of Growth" to everyone. |
| Color | `variant="outline"` neutral only. Never `destructive`, `warning`, or a vivid semantic tint — being on a lower plan is not an error state. |
| Data source | A static frontend constant (`PREMIUM_REPORT_SLUGS`) mirroring the edge functions' `PREMIUM_REPORT_TYPES`. **No subscription fetch on the hub index** — D-04 forbids data fetching there, so the index cannot and must not know the viewer's tier. |
| Enforcement | The Edge Function 402 remains the **sole** gate. `export-report/index.ts:24` (checked :72) and `generate-pdf/index.ts:31` (checked :322). No client-side disable, no route guard, no proxy change (D-13). |
| Free-tier click | The existing rail fires unchanged: `PaywallError` (`report-keys.ts:148`) → sonner toast titled **"Upgrade required"**, description from the edge function (default *"This feature requires a Growth or Max subscription."*), action **"See plans"** → `upgrade_url` (`/billing/plans?source=reports_gate`). **The hub must not introduce a second paywall pattern.** |

### Which entries actually carry the badge — evidence-based, not guessed

Only surfaces whose CTA provably reaches a gated `reportType`:

| Surface | CTA | Edge call | `reportType` | Gated | Badge |
|---------|-----|-----------|--------------|:---:|:---:|
| `/reports/year-end` | Download PDF | `generate-pdf` | `year-end` | yes | **yes** |
| `/reports/tax-documents` | Download PDF | `generate-pdf` | `financial` | yes | **yes** |
| `/reports/generate` | PDF / Excel buttons | none — client-side `jspdf` + `sheetjs` | n/a | **no** | **no** |
| `/reports/year-end` | Year-End CSV, 1099 CSV | none — client-side `downloadCsv()` | n/a | **no** | **no** |
| `/reports/income-statement`, `/reports/cash-flow` | **dead** `Export`/`Download` button (rendered, no `onClick`) | none | n/a | n/a | **no** |

`income-statement` and `cash-flow` appear in `PREMIUM_REPORT_TYPES` only as `export-report?type=` query values that no UI currently sends. Badging those tiles would be a false claim about what is gated. Do not badge them.

**Correction (checker verification):** those two routes do NOT lack an export CTA — `income-statement-page-header.tsx` and `cash-flow-header.tsx` each render a visible `Export`/`Download` button **with no `onClick` handler at all**. The no-badge conclusion is unchanged (a dead button reaches no edge call and gates nothing), but the planner is inheriting a **non-functional CTA, not an absent one**, and moving these pages carries it along. Fixing it is out of scope — this phase moves and consolidates, it does not repair capability — but it must not be mistaken for working behaviour during E2E authoring.

**Recorded, out of scope:** `reportMutations.downloadYearEndCsv` and `download1099Csv` (`report-keys.ts:268,276`) call the gated `export-report` function but are wired to no UI — the year-end page does client-side CSV instead. Those two gate paths are therefore currently unexercised by the product. Note it in verification; do not "fix" it in this phase.

## Inherited Vocabulary Guard (D-18 — live regression risk found)

Verified state of the merge:

### Design Problem 2 — `/documents` landing composition (D-14..D-17)

**Locked and non-negotiable:** vault entry + lease-template entry + **four separate** printable template cards + a recent-documents list. Six tiles plus a list. The two real problems are (a) six tiles skew weight toward templates when the vault is the primary destination, and (b) the recent list overlaps `/documents/vault` and the two must not visibly disagree.

**Both are solved by one move: the recent-documents list lives INSIDE the vault panel, and the vault panel is a full-width primary band that the templates cannot compete with.**

#### Three-band descending-weight ladder


**Why this fixes balance (a):** the vault occupies full width, carries a `size-12` primary-tinted medallion, is the page's only filled primary `Button`, and contains live content — roughly half the page's vertical real estate. Below it, six tiles read as **1 + 4** across two labelled bands with progressively smaller medallions (`size-10` → `size-8`) and padding (`p-5` → `p-4`) and neutral `bg-muted` medallions. Tile count is untouched (D-16 satisfied: four separate cards); the hierarchy is carried by size, width, color budget, and content — not by deleting anything.

**Why this fixes overlap (b) — two independent guarantees:**

1. **Semantic:** nesting the list inside the vault panel, under a `Separator`, below the "Open the vault" CTA, makes it read unambiguously as *a preview of what is in the vault* rather than a second, competing document surface. It is subordinate by position, never a sibling band.
2. **Structural — they cannot disagree, by construction:** the list calls `documentSearchQueries.list({ page: 0 })` from `#hooks/api/query-keys/document-search-keys` with **no filters** and slices the result to the first 5 client-side. That is the exact factory the vault client calls (`src/components/documents/documents-vault.client.tsx:230-238`) → the same `search_documents` RPC → the same `mapDocumentRow` boundary mapper → the same TanStack Query cache entry. The RPC's unfiltered ordering is `d.created_at desc` (verified: `20260426043911_v25_phase_63_search_documents_filter_extension.sql:110`), so "recent" is exactly the vault's own first rows.

**Scope of the "same cache entry" claim (checker-verified):** it holds for the vault's *default, unfiltered landing state* — `queryParam=""`, `entityType=undefined`, `categories=[]`, `from`/`to=""`, `page=0` — which normalizes to the identical query key as `documentSearchQueries.list({ page: 0 })`. Once the owner types a search or applies a filter the vault moves to a different key, and the landing's list legitimately keeps showing unfiltered recents. That is correct behaviour, not drift: the two only ever share a cache entry when they are asking the same question. **Building a second query, a second mapper, or a direct `.from('documents')` select is a blocking violation of this contract.**

- `src/app/(owner)/documents/page.tsx` is a **Server Component**; only the recent-documents panel is a `'use client'` island. Server-rendering the list would create a second fetch path and forfeit guarantee (b).
- The file carries a short comment recording that **DOCS-01 superseded** the earlier `permanentRedirect("/documents/vault")` decision and why, so the reversal reads as deliberate (D-17).
- Band headings are real `<h2>`; each band is `<section aria-labelledby>`. Band 1's heading is the vault title itself.
- Every tile is one `<Link>`, whole-card clickable, no nested interactive elements. Medallion icons and the `ArrowRight` are `aria-hidden="true"`.
