before body validation, so an invalid body exercises the limit and sends no mail:


## MISTAKE MADE AND CORRECTED

I set `SENTRY_DSN` to an EMPTY STRING in production. The extraction returned zero characters and I
piped it straight into `supabase secrets set` without checking. Removed within a minute
(`secrets unset`, verified back to 50). An empty secret is worse than an absent one because it
reads as configured.

The rewrite that caught it validates the value looks like a DSN BEFORE setting, and it is what
surfaced the real blocker: **Vercel marks 40 of its 72 production variables as Sensitive, so their
values export blank** -- `SENTRY_DSN` and `NEXT_PUBLIC_SENTRY_DSN` among them. The DSN was never
retrievable from Vercel by any means, so the earlier plan to copy it across could not have worked.

Resolved canonically instead: fetched from the Sentry API (`find_dsns`), which is the authoritative
source. Two client keys exist for `tenant-flow`, both routing to project `4510717297033216`; used
the one named `tenant-flow`.
