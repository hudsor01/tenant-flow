Decision (W3, balance/late math intentionally lives in two places): the DB stays the single source of truth for the aggregate summary + late-count via get_lease_ledger_summary (55-02). We deliberately ACCEPT a mirrored client-side derivation in ledger-math.ts because the ledger table is interactive (client-side per-row running balance, sort/filter) and cannot round-trip the DB per row without breaking that interactivity. The duplication is made explicit: GRACE_PERIOD_DAYS = 5 is documented in-source as the mirror of the SQL interval '5 days' literal, and the mirrored-constant drift threat (T-55-12) is unit-asserted (GRACE_PERIOD_DAYS === 5) so the two cannot silently diverge.

<!-- Pure module contract consumed by the ledger tab (55-07). Dollars end-to-end; NO cents. -->

export const GRACE_PERIOD_DAYS = 5;

export type LedgerEntry = {
  id: string;
  kind: 'charge' | 'receipt';
  type: string;            // 'rent'|'late_fee'|'manual_charge'|'credit'|'opening' for charges
  amount: number;          // signed DOLLARS
  entryDate: string;       // YYYY-MM-DD
  dueDate: string | null;  // charges only
  reversesId: string | null;
  chargeId: string | null; // receipts only
  receiptsSum: number;     // charges only: Σ receipts against this charge (dollars)
};

export type ChargeState = 'paid' | 'partial' | 'unpaid' | 'late';

export function deriveChargeState(chargeAmount: number, receiptsSum: number, dueDate: string | null, today: Date): ChargeState;
export function isLate(remaining: number, dueDate: string | null, today: Date): boolean;
export function computeRunningBalance(orderedEntries: LedgerEntry[]): Array<LedgerEntry & { runningBalance: number }>;
</interfaces>
</context>

<feature>
  <name>Ledger derivation math (deriveChargeState / isLate / computeRunningBalance)</name>
  <files>src/lib/ledger/ledger-math.ts, src/hooks/api/__tests__/rent-ledger-balance.test.ts</files>
  <behavior>
    - deriveChargeState: receiptsSum >= chargeAmount → 'paid'; 0 < receiptsSum < chargeAmount and not late → 'partial'; receiptsSum = 0 (or remaining > 0) and late → 'late'; otherwise 'unpaid'.
    - isLate boundary: remaining > 0 AND today > dueDate + 5 days. dueDate + exactly 5 days → NOT late; dueDate + 6 days → late. dueDate null → never late.
    - computeRunningBalance: running balance is cumulative Σ(charge amounts) − Σ(receipt amounts) in entry order; charges add their signed amount, receipts subtract their amount; dollars, never cents.
    - Signed amounts: a credit charge (negative amount) reduces the running balance; a reversal row (negative, reversesId set) nets its original to zero.
    - Money: every value is dollars; the module contains no cents math (spaced or unspaced *100 / /100, or formatCents().
  </behavior>
