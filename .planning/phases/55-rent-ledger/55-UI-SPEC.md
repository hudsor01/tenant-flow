# Phase 55 — UI Design Contract

> Visual and interaction contract for the Rent Ledger phase. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **This phase surfaces a new landlord-only bookkeeping subsystem over the EXISTING, LOCKED TenantFlow design system. It invents no new visual language.** Every token below is the real value read from `src/app/globals.css` (`@theme`). Every surface composes primitives already in `src/components/ui/` and mirrors two established analogs: the lease-detail tab shell + key-metric cards (`src/components/leases/detail/lease-details.client.tsx`) for the per-lease ledger, and the dashboard KPI bento (`src/components/dashboard/components/kpi-bento-row.tsx` + `Stat` in `src/components/ui/stat.tsx`) for the collection-rate KPI. Zero new npm deps, zero new shadcn registry blocks (locked by RESEARCH.md "Standard Stack").
>
> **Load-bearing money rule (D-00):** all ledger amounts are `numeric(10,2)` **dollars**. Every display path uses `formatCurrency(dollars)` from `src/lib/utils/currency.ts` — **never** `formatCents`, **never** `* 100` / `/ 100`. Any cents math on a ledger amount is the v8.0 100× bug (MONEY-01/02) recurring and is a blocking violation. All money renders with `tabular-nums`.

## Typography

Font family `--font-sans` throughout. **Two weights carry all semantics: 400 regular and 600 semibold.** Four sizes cover every ledger surface. All money uses `font-variant-numeric: tabular-nums` (via `tabular-nums`).

| Role | Size | Weight | Line height | Applied to |
|------|------|--------|-------------|-----------|
| Heading | 16px (`text-base` / `typography-h3` = `--text-title-3`) | 600 | 1.35 (`--leading-snug`) | Ledger tab section heading; `CardTitle` on balance summary + KPI; dialog `DialogTitle` |
| Body / row | 14px (`text-sm`) | 400 | 1.35 (`--leading-snug`) | Table cell text (date, description, method); form input text; charge/receipt descriptions |
| Money — inline | 14px (`text-sm`) | 600 | 1.35 | Amount + running-balance cells in the ledger table (`tabular-nums`) |
| Metadata / caption | 12px (`text-xs`) | 400 | 1.5 (`--leading-normal`) | Relative dates, badge labels, "Scheduled"/"Collected" sublabels, empty-state description, KPI helper line |

**Emphasis money (cited exception, not a new size):** the **per-lease balance summary** value uses `text-xl` (20px, 600, `tabular-nums`) to match the existing lease key-metric cards (`lease-details.client.tsx` renders `Monthly Rent` at `text-xl font-semibold tabular-nums`). The **dashboard collection-rate KPI** value reuses the existing `typography-stat` (32px, `--text-stat`) token from the dashboard KPI bento contract (`03-UI-SPEC`) via `StatValue` + `NumberTicker` — reused from an existing surface, not introduced here. These two are cited exceptions tied to established surfaces; do not add any further size or a third weight to the core ledger surfaces.

## Color

Tokens are oklch CSS custom properties in `globals.css`; both light and dark values already defined. **Never hard-code hex/oklch in components** — reference the token utilities. No gradient text (globally forbidden). Muted text uses `text-muted-foreground` (never bare `text-muted`); surfaces use `bg-card`/`bg-background` (never `bg-white`).

| Role | Token | Usage |
|------|-------|-------|
| Dominant (60%) | `--color-background` (`bg-background`) | Ledger tab canvas; `/leases/[id]` page behind cards; dashboard canvas |
| Secondary (30%) | `--color-card` (`bg-card`) / `--color-popover` (`bg-popover`) | Balance summary card; ledger table container; KPI card; dialog surfaces; every row sits on this |
| Accent (10%) | `--color-primary` (`bg-primary` fill / `text-primary-text` text / `text-primary-foreground` on fill) | See reserved-for list below |
| Destructive | `--color-destructive` (fill/tint) / `--color-destructive-text` (glyph, AA-safe both themes) | Reversal confirm action button; `Late` status tint (via `status-overdue`) |

**Accent (primary) reserved for — explicit list, nothing else:**
1. Primary CTA button fills: **Record receipt**, **Start tracking rent** (`Button` default variant = `bg-primary text-primary-foreground`).
2. The collection-rate KPI value + its `StatIndicator` chip when status is Excellent/Good (`icon-bg-primary` / `text-primary-text`).
3. Text link affordances inside the ledger tab (e.g. "Set a start date" prompt link in the empty state) — `text-primary-text hover:underline`.
4. The active **Ledger** tab indicator (shadcn `TabsTrigger` active state — already primary-tinted).
5. Focus ring (`--color-ring`, already global via `*:focus-visible`).

Accent is **NOT** applied to: ledger row text, running-balance figures (neutral `text-foreground`), the "Add line" / "Reverse" secondary controls (outline/ghost), or the money summary numbers. Secondary actions use `Button variant="outline"` or `variant="ghost"`.

### Semantic ledger-state palette (derived states — D-02/D-03)

Each charge's derived state renders as a `Badge` using the existing semantic variant + AA-safe `-text` companion (CLAUDE.md vivid-token rule: vivid token for the fill/border tint at 10–20%, `-text` companion for the glyph/label). These map to existing `globals.css` status utilities — no new colors.

| State | Meaning | `Badge` variant / utility | Label token | Icon (lucide) |
|-------|---------|---------------------------|-------------|---------------|
| Paid | Σ receipts ≥ charge amount | `variant="success"` (`bg-success/10 text-success-text border-success/20`) | `text-success-text` | `CircleCheck` |
| Partial | 0 < Σ receipts < charge amount | `variant="warning"` | `text-warning-text` | `CircleDashed` |
| Unpaid (in grace) | Σ receipts = 0, not yet past `due_date + 5d` | `variant="secondary"` (neutral) | `text-muted-foreground` | `CircleDashed` |
| **Late** | unpaid remaining AND `due_date + 5d < today` | `status-overdue` utility / `variant="destructive"` tint (`bg-destructive/10 text-destructive-text border-destructive/20`) | `text-destructive-text` | `TriangleAlert` |
| Credit | `type='credit'` line (reduces balance) | `variant="info"` (`bg-info/10 text-info-text`) | `text-info-text` | `Undo2` (or `MinusCircle`) |
| Opening | `type='opening'` track-since seed row | `variant="outline"` (muted) | `text-muted-foreground` | `Flag` |
| Reversed / reversal | row with `reverses_id`, or an original that was reversed | muted + `line-through` on the amount, `variant="outline"` "Reversed" chip | `text-muted-foreground` | `Undo2` |

**KPI status colors (D-08, via `getCollectionRateStatus`):** the helper returns `text-success` (≥95 Excellent), `text-info` (≥85 Good), `text-warning` (≥70 Fair), `text-destructive` (<70 Poor). The executor MUST swap the helper's placeholder `icon` strings (`"TARGET:"`, `"[OK]"`, `"WARNING:"`, `"[DOWN]"`) for lucide icons in the card (`TrendingUp`/`CircleCheck`/`TriangleAlert`/`TrendingDown`) — those strings are labels, not emojis, and must not render as text.

## Copywriting Contract

Voice: **landlord-only bookkeeping**. Tenants are records, not users — **no** tenant-facing language, **no** "pay now" / "collect" / payment-rail verbs. Money is **recorded/received**, not processed. Sentence case, no em-dashes in user-facing strings, no emojis (lucide only).

| Element | Copy |
|---------|------|
| Primary CTA (has a ledger, charge selected) | **Record receipt** |
| Primary CTA (no ledger yet) | **Start tracking rent** |
| Secondary action (add manual line) | **Add line** |
| Secondary action (correct an entry) | **Reverse entry** |
| Track-since dialog title | **Start tracking rent for this lease** |
| Track-since dialog description | **Pick the date to start the ledger from and the balance owed on that date. History before this date isn't rebuilt.** |
| Track-since date field label | **Start tracking from** |
| Opening balance field label | **Balance owed as of this date** (helper: *Enter 0 if the tenant was current.*) |

| Add-line dialog title | **Add a charge or credit** |
| Add-line field labels | **Type** (Late fee / Other charge / Credit) · **Amount** · **Date** · **Description** |
| Reverse confirmation title | **Reverse this entry?** |
| Reverse confirmation body | **This posts an offsetting entry that cancels "{description}" ({amount}). The original stays on the ledger for your records — nothing is deleted.** |
| Reverse confirm button | **Reverse entry** (destructive variant) |
| No-ledger empty — title | **No rent ledger yet** |

| Revenue relabel — collected | **Collected** (tooltip: *Payments you've recorded against charges this period.*) |

| Success toasts | **Rent tracking started** · **Payment recorded** · **Line added** · **Entry reversed** |

### Validation / error copy

| Field / case | Message |
|--------------|---------|
| Receipt amount empty or ≤ 0 | **Enter an amount greater than $0.** |
| Receipt no charge selected | **Choose which charge this payment applies to.** |
| Receipt date empty | **Choose the date you received this payment.** |
| Receipt method empty | **Add a label for how this was received (cash, check, Zelle).** |
| Add-line amount empty or ≤ 0 | **Enter an amount greater than $0.** |
| Add-line type not chosen | **Choose whether this is a charge or a credit.** |
| Track-since date empty | **Choose a start date for the ledger.** |
| Track-since opening balance invalid | **Enter the balance owed (0 if the tenant was current).** |
| Mutation failure (any) | **Couldn't save that. Please try again.** + inline `Retry`; never a raw PostgREST error (uses `handlePostgrestError`) |
| Ledger load error | **Couldn't load the ledger.** + `Retry` |

**Destructive actions (list + confirmation approach):**
- **Reverse entry** — the ONLY destructive-styled action. Ledger is append-only (D-06): nothing is edited or deleted. "Reverse" appends an offsetting entry. Confirmed via `ConfirmDialog` (`confirmVariant="destructive"`, copy above). When reversing a charge that already has receipts, the confirm copy notes the paired receipt reversal (Pitfall 4) so the balance nets correctly.

**No double-counting rule (copy-level, D-07):** "Scheduled" and "Collected" always render as two explicitly-labeled figures with distinct labels and tooltips; they are **never** summed into a single "Revenue" number and never share a value. The collection-rate KPI is the only place they combine — as the ratio collected ÷ scheduled.

## Surface Layouts

### 1. Per-lease Ledger tab (`/leases/[id]` → new `Ledger` tab — LEDGER-02/03/05/06)
- Extend the `Tabs` at `lease-details.client.tsx:186` to `grid-cols-4`: `Details · Ledger · Timeline · Terms`. New `TabsContent value="ledger"` renders a `'use client'` island `LedgerTab`.
- **Balance summary strip** (top): a `Card grid gap-4 sm:grid-cols-3` with three `Stat`/metric cards — **Balance** (20px `tabular-nums`; `text-destructive-text` if > 0 owed, `text-success-text` if ≤ 0), **Charged** (Σ charges), **Received** (Σ receipts). Fed by `get_lease_ledger_summary()`. A `Late` count `Badge` (destructive) appears next to Balance when `late_count > 0`.
- **Action row:** `Record receipt` (primary), `Add line` (outline), both open dialogs. Disabled until the lease is being tracked.
- **Ledger table:** shadcn `Table`, columns `Date · Description · Type · Charge · Receipt · Balance · [state badge] · ⋯`. Rows chronological; running balance right-aligned `tabular-nums`. Reversed rows dimmed + `line-through` amount. Per-row overflow `⋯` menu exposes **Reverse entry** (icon-only `Undo2` button carries `aria-label="Reverse entry"`).
- **Empty (not tracked):** full `Empty` compound (title/body/CTA above). **Loading:** 5 `Skeleton` rows. **Error:** inline copy + `Retry`.

### 2. Record-receipt dialog (LEDGER-02)
- `Dialog` (mirror `renew-lease-dialog.tsx`), TanStack Form + zod. Fields: **Applies to charge** (`Select` of open/partial charges, showing `{period} · {remaining} due`), **Amount received** (`Input` numeric, dollars), **Date received** (`Calendar` in `Popover`), **Method** (`Input` + suggested chips). Footer: `Cancel` (ghost) + `Record receipt` (primary, pending → spinner). Partial payments = a receipt for less than remaining; multiple receipts allowed per charge (D-02). No cap enforced; overpayment lands as a credit balance.

### 3. Add-line dialog (LEDGER-05)
- `Dialog` + TanStack Form. **Type** `Select` (Late fee / Other charge / Credit), **Amount** (dollars — sign applied by type: charges positive, credit negative), **Date** (`Calendar`), **Description** (`Textarea`). Manual only — no auto-late-fee anywhere. Footer: `Cancel` + `Add line`.

### 4. Track-since onboarding dialog (LEDGER-04)
- `Dialog` triggered from the empty state's `Start tracking rent`. **Start tracking from** (`Calendar`) + **Balance owed as of this date** (`Input`, dollars, 0 allowed). Writes `leases.ledger_start_date` + a `type='opening'` charge. On success → the ledger renders (opening row + generated charges from track-since forward).

### 5. Collection-rate KPI (dashboard — LEDGER-08)
- `Stat` card (mirror `kpi-bento-row.tsx`): `StatLabel` "Collection rate", `StatValue` = `formatPercentage(rate)` via `NumberTicker` (32px `typography-stat`, honors reduced motion), `StatIndicator` colored by `getCollectionRateStatus()`, `StatDescription` "Collected ÷ scheduled, this month". Zero-data → 0% + honest helper. Wired into `ownerDashboardKeys.financial`; ledger mutations invalidate related keys + `ownerDashboardKeys.all`.

### 6. Scheduled vs Collected relabel (LEDGER-07)
- On every existing revenue surface (dashboard revenue figures, financial overview), the lease-derived figure gets the explicit **Scheduled** label + tooltip; a new **Collected** figure appears beside it with its own label + tooltip. Visually distinct (separate `StatLabel`s / legend entries, different chart series where a chart exists). Never summed, never a single "Revenue" number.

## Interaction & State Contracts

| State | Contract |
|-------|----------|
| Charge paid-state | Derived in the summary RPC (`Σ receipts` vs `charge.amount`); rendered as a `Badge`. Never a stored/mutable column. |
| Late flag | Derived: unpaid remaining AND `due_date + 5 days < today` (fixed 5-day grace, D-03). `status-overdue` tint + `TriangleAlert`. Boundary: +5 days not late, +6 late. |
| Money display | `formatCurrency(dollars)` only. Never `formatCents`, never `* 100` / `/ 100`. `tabular-nums`, right-aligned in tables. |
| Append-only | No edit/delete affordance on any amount. The only correction is `Reverse entry` → appends an offsetting row (`reverses_id`). Reversed rows dim + strike; originals stay visible. |
| Reverse a charge with receipts | Confirm copy notes the paired receipt reversal; the composed mutation posts both negations so the balance nets to zero (Pitfall 4). |
| Method field | Free-text label + suggested chips; NO payment-rail/card/ACH-connect UI, NO "Pay now". |
| Mutations | On success: toast + invalidate `rentLedgerKeys.forLease(leaseId)` + `ownerDashboardKeys.all`. Optimistic where safe; append-only so no rollback of edits. |
| Loading | `Skeleton` rows / KPI skeleton tile — never a blocking spinner over the surface. |
| Empty | `Empty` compound (full on the ledger tab when untracked). Always at least the opening row once tracking starts. |
| Error | Inline copy + `Retry`; `handlePostgrestError` — never a raw PostgREST/Supabase error string to the user. |
| Focus / keyboard | Dialog focus trap + Escape (radix default); icon-only Reverse button has `aria-label`; forms `autoFocus` the primary field; date pickers keyboard-navigable. |
| Mobile (375px) | Ledger table horizontally scrollable (`overflow-x-auto`) with Date + Balance pinned-visible priority; dialogs full-width; controls at 44px touch target. |
| Motion | KPI `NumberTicker` and any entry animation honor `prefers-reduced-motion` (global rule). No custom animation introduced. |
