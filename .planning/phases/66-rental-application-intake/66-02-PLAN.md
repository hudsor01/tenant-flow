<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| applicant browser → Edge Function payload | Everything in the request body is attacker-controlled. This plan writes the validator that is the authoritative gate — the client zod schema is UX only. |
| bot → public form | The honeypot and timing guard are the only defences that keep working when Upstash is unreachable (`rate-limit.ts:159` fails open, D-04). |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-66-08 | Tampering | honeypot / timing evasion | mitigate | `isHoneypotTripped` treats any non-empty value as tripped including non-strings; `isTimingSuspicious` rejects unparseable, future and stale timestamps. Explicitly documented as a bot filter, not a control — the fail-closed bound is plan 66-04's DB cap. |
| T-66-11 | Information Disclosure | SSN / DOB / financial data entering the system | mitigate | `parseSubmissionPayload` rejects unknown keys before anything else, so an `ssn` key produces a rejection rather than a silently stripped field that still transited the wire into a log. Zod `.strict()` mirrors it browser-side. Pinned by a FORBIDDEN-list test that fails when a new forbidden key is added to either contract. |
| T-66-09 | Tampering | stored XSS via applicant free text | mitigate | Length caps at the validator; no HTML is ever constructed from these values (D-10 means applicant text never reaches an email template). The disclaimer test asserts the constant contains no `<`. React escaping covers the owner surfaces (plans 66-13/66-15) and `dangerouslySetInnerHTML` is prohibited there. |
| T-66-02 | Information Disclosure | token-state enumeration via differential copy | mitigate | `TOKEN_UNAVAILABLE_COPY` is one constant, and a test asserts its body names none of the three states. Structural, not procedural. |
| T-66-SC | Tampering | npm/deno package installs | mitigate | Zero packages. The Deno validator is hand-written specifically to avoid adding `zod` to `supabase/functions/deno.json`, which would be a new runtime dependency the milestone forbids. |
</threat_model>
