<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| PostgREST response → typed application state | An untyped cast here produces runtime errors on the owner's dashboard and, worse, silently mistypes nullable fields as non-null. |
| owner browser → application rows | RLS is the gate; this layer must not widen it by selecting more than the surface needs. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-66-33 | Tampering | untyped PostgREST boundary producing wrong-typed data | mitigate | `mapRentalApplicationRow` / `mapApplicationLinkRow` follow the `mapDocumentRow` idiom; zero `as unknown as`, gated by grep. Numeric coercion is explicit because PostgREST returns `numeric` as a string on some paths. |
| T-66-34 | Information Disclosure | over-selecting applicant PII into the browser | mitigate | The list factory enumerates ~10 columns; `select("*")` is confined to the detail view, which genuinely renders every field. The queue would otherwise cache every applicant's full PII in the browser. |
| T-66-09 | Tampering | stored XSS from applicant free text | mitigate | Values stay strings through the mapper and are rendered by React, which escapes by default. No `dangerouslySetInnerHTML` in this layer or the ones consuming it. |
| T-66-14 | Elevation of Privilege | owner mutating another owner's row | transfer | Every mutation calls a plan 66-04 RPC that re-checks `auth.uid()` server-side. This layer never assumes the client-side owner id is authoritative. |
| T-66-35 | Repudiation | pager reporting a wrong total from `data.length` | mitigate | `{ count: 'exact' }` with a zero-occurrence grep on `data.length` / `rows.length`. |
| T-66-SC | Tampering | package installs | mitigate | Zero packages; `@tanstack/react-query` and `@supabase/supabase-js` are already present. |
