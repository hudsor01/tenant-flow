**NULLABILITY note — write this reasoning into the migration header.** Several of the
nullable columns above are *required on the form* (phone, move-in date, address, income,
occupant count's siblings, reference 1). They are nullable at the column level ONLY so
`anonymize_old_rental_applications()` (plan 66-05) can clear them. Required-ness is
enforced twice at write time — by the strict payload validator in the Edge Function and
again by an explicit null-check inside `submit_rental_application` — and never by a
NOT NULL constraint that would make the retention sweep impossible. A reviewer who
"tightens" these to NOT NULL breaks APPLY-05.

`public.rental_applications` policies — one policy per operation per role, never `FOR ALL`:
- `rental_applications_select` — `for select to authenticated using (owner_user_id = (select auth.uid()))`
- `rental_applications_delete` — `for delete to authenticated using (owner_user_id = (select auth.uid()))`
- **No INSERT policy and no UPDATE policy, for either role.** Write a comment block
  explaining both omissions, because both are deliberate and a reviewer will otherwise
  read them as gaps:
  - No INSERT: APPLY-02 mandates that every applicant row is written by the
    `verify_jwt=false` Edge Function through a SECURITY DEFINER RPC. An anon INSERT
    policy is not merely forbidden, it is structurally incapable of enforcing the
    per-link cap atomically or rate-limiting anything, and it would expose a writable
    PostgREST surface that bypasses the honeypot, the timing guard and the caps entirely.
  - No UPDATE: this is a deliberate hardening beyond `66-RESEARCH.md`'s suggested
    UPDATE-with-`with check` policy. Every owner mutation (status, notes, conversion)
    goes through an owner-gated SECURITY DEFINER RPC in plan 66-04. Removing the UPDATE
    policy removes the row-re-parenting threat class outright rather than guarding it,
    and it prevents an owner rewriting `applicant_email` — the fair-housing record the
    720-day window exists to preserve.

`public.rental_application_links` policies:
- `rental_application_links_select` — `for select to authenticated using (owner_user_id = (select auth.uid()))`. This is the policy that makes the D-03a re-copyable `raw_token` owner-only.

Every policy wraps `auth.uid()` in a subselect — `(select auth.uid())` — per CLAUDE.md.
