## Why the URL is always visible and never shown once

D-03a, and it is the decision this whole band exists to express. `/sign`'s hash-only,
shown-once model protects a secret credential held by one tenant. This token is the
opposite: the owner *publishes* it, pasting it to Zillow on Monday and Craigslist on
Thursday over a 60-day listing. Repeat retrieval is the primary use case, not the
exception. A shown-once model would force a rotation every time the owner needs the link
again, silently breaking every listing already posted — a guaranteed recurring failure
traded against a hypothetical one. So: a persistent read-only `Input` holding the URL and a
copy button. No reveal-once dialog, no regenerate-to-retrieve.
</objective>

**Active state.** The URL comes from `applicationLinkUrl(row.raw_token)`, which builds from
`NEXT_PUBLIC_APP_URL`. **Never `window.location.origin`** — the Edge Function's CORS check
is an exact string comparison against `NEXT_PUBLIC_APP_URL`, so a link copied from a `www.`
host or a preview deployment produces a URL whose submissions fail CORS for the applicant
while working fine for the owner who copied it. That failure is invisible to the owner and
total for the applicant. Comment it at the call site.

The `Input` is `readOnly`, `font-mono text-xs`, with `onFocus` selecting all — so a
keyboard user can copy without the button. It is always present and always populated; there
is no reveal step.

**Copy feedback — both, because a toast can be missed on mobile:**
1. `toast.success("Application link copied")` (sonner).
2. The icon swaps `Copy` → `Check` for 2000ms **and the button's `aria-label` swaps to
   "Application link copied"**, so the change is announced, not only seen. An icon swap
   alone is invisible to a screen-reader user, and this is the only icon-only control in
   the phase.

Icon-only buttons carry `aria-label`, never `title` (CLAUDE.md accessibility).

**Revoke** — `ConfirmDialog`, `confirmVariant="destructive"`, `confirmText` "Revoke link",
title "Revoke this link?", description exactly:

link is no longer available. Applications you have already received are not affected. You
can create a new link afterward."
That middle sentence is load-bearing: without it an owner reasonably fears revoking will
delete the applications they have collected.

The trigger label is the short `Revoke`; the button that commits is the explicit
`Revoke link`. Comment that this is deliberate (§B-8) so a reviewer does not "fix" the
trigger to `Revoke link` — naming the object twice in a row reads as a stutter, and the

**Create** calls `createApplicationLinkMutationOptions` with the 60-day default. The RPC
refuses when an active link already exists (plan 66-04), so surface that rejection as a

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| owner clipboard → public listing sites | The copied string becomes a public capability URL. Its origin determines whether applicants can submit at all. |
| owner's stored raw token → anyone who reads the panel | The raw token is deliberately readable here (D-03a); the RLS SELECT policy is what keeps that scoped to the owner. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-66-15 | Information Disclosure | raw token readable in the owner UI | accept | D-03a, decided with reasoning. The owner-only RLS SELECT policy (plan 66-01) plus the `anon` revoke bound it. The token's entire purpose is to be published; unguessability, not confidentiality, is the security property, and 256 bits preserves that whether or not the raw value is stored. |
| T-66-44 | Denial of Service | link built from a non-canonical origin, failing CORS for every applicant | mitigate | `applicationLinkUrl` builds from `NEXT_PUBLIC_APP_URL`; zero `window.location` gated by grep; the unit test asserts the full URL against an origin jsdom does not share. The failure is asymmetric — it works for the owner and fails for every applicant — so it must be caught mechanically. |
| T-66-45 | Denial of Service | accidental revoke breaking a live listing | mitigate | `ConfirmDialog` with `confirmVariant="destructive"`, a description naming exactly what breaks and what does not, and a test asserting the mutation does not fire until the confirm button is clicked. |

| T-66-47 | Information Disclosure | a revoked link mislabelled Expired | mitigate | `applicationLinkState` orders revoked above expired, tested at both the unit level (66-09) and the render level here. Mislabelling hides that the owner revoked it deliberately. |
| T-66-SC | Tampering | package installs | mitigate | Zero packages; `sonner`, `ConfirmDialog` and `Empty` all already exist. |
