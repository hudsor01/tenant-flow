Each row is one `Item size="default"` `asChild` over a `<Link>` carrying **both**

`a:not([role="button"]):not(.button):not([class*="button"])` rule sets

`buttonVariants` satisfies all three `:not()` guards, so the rule applies. Without
`text-foreground` the entire row tints accent-blue. Phase 65 hit exactly this.

`ItemTitle` is `flex w-fit`; a flex container has nothing to clip, so `text-overflow:
ellipsis` never fires, and without the parent's `min-w-0` the flex item's `min-width: auto`
floor stops `w-full` from constraining anything. Comment both.

`ItemTitle` is `font-normal`, overriding the primitive's `font-medium`, to stay inside the
phase's two-weight contract. `ItemDescription` is `text-xs mb-0` and renders
`{property} · Unit {n} · {relative date}` via `formatRelativeDate`.

`ItemActions` holds the status badge and **nothing else** — no buttons in the row. The
whole row is the affordance; a nested interactive element inside a whole-row `<Link>` is
invalid and breaks keyboard navigation.

No fixed row height and no `line-clamp` on the meta line. At 375px a long property name
wraps and the row grows; that is correct.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| applicant free text → owner's authenticated session | Attacker-controlled strings rendered inside a logged-in dashboard. This is the stored-XSS sink. |
| owner A's session → owner B's rows | RLS is the gate; the client must not assume otherwise or paginate around it. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-66-09 | Tampering | stored XSS from applicant name / free text into the owner dashboard | mitigate | Every applicant value renders as a React child, which escapes by default. **No `dangerouslySetInnerHTML` anywhere in this phase**, and no HTML is constructed from applicant strings. Length caps were applied at the validator (plan 66-02) so a pathological value cannot break the layout either. |
| T-66-36 | Information Disclosure | cross-owner rows appearing in the queue | transfer | RLS on `rental_applications` scoped by `owner_user_id` (plan 66-01), pinned by plan 66-10's dual-client tests. The client applies no owner filter of its own and must not — a client-side filter would imply the server one is optional. |
| T-66-35 | Repudiation | pager misreporting the corpus size | mitigate | `total` from `{ count: 'exact' }`, asserted with a mocked count that differs from the row-array length. |
| T-66-43 | Information Disclosure | raw PostgREST error text surfaced to the owner | mitigate | `handlePostgrestError` on every failure path, and a test asserting no `PGRST` substring reaches the DOM. Raw messages leak schema and column names. |
| T-66-34 | Information Disclosure | full applicant PII cached in the browser for every queue render | mitigate | The list query enumerates ~10 columns (plan 66-09); the queue renders name, property, unit, date and status only. |
| T-66-SC | Tampering | package installs | mitigate | Zero packages; every primitive already exists in `src/components/ui/`. |
