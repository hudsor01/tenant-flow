Create `src/app/apply/[token]/apply-context.ts`, mirroring `sign-context.ts` structurally.

`fetchApplyContext(token)` POSTs `{ action: "context", token }` to
`${NEXT_PUBLIC_SUPABASE_URL}/functions/v1/apply-token` with `cache: "no-store"`, returning
the parsed body on 2xx and `{ valid: false, reason: "context_error" }` on any non-2xx,

**Deliberately do NOT port `REASON_MESSAGE`.** Write a header comment explaining the
divergence: `sign-context.ts` maps each reason to distinct copy because each of its states
means something different to the tenant. Here, invalid, expired and revoked must be
**indistinguishable** — a differentiated message turns the page into a token oracle. So
this module returns the raw reason and the page renders `TOKEN_UNAVAILABLE_COPY` for all
of them, with `context_error` as the ONLY branch that renders differently, because a
transport fault is genuinely recoverable ("try again") while a bad token is not.

`formatListingRent` uses the existing `formatCurrency` from `#lib/utils/currency` — do not
hand-roll a formatter — and returns `null` rather than a placeholder when the value is
null, because UI-SPEC §A-5 omits the row entirely in that case.

`vi.hoisted()` + `vi.stubGlobal`.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| unauthenticated internet → this page | No session, no cookie, no gate. The token in the URL is the entire authorization story. |
| Next.js server → Edge Function | The context call is server-to-server, so it carries the Vercel egress IP and is exempt from CORS — which is why the per-token rate-limit bucket exists on that path. |
| search engine → this page | The URL is pasted into public listings and will be crawled. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-66-02 | Information Disclosure | token-state enumeration via the rendered page | mitigate | One `TOKEN_UNAVAILABLE_COPY` constant serves invalid, expired, revoked and unit-deleted; `apply-context.ts` deliberately ships no per-reason message map; the page never branches on the reason inside the unavailable card. HTTP is always 200. |
| T-66-10 | Information Disclosure | capability URL indexed and surfaced in search | mitigate | `robots: { index: false, follow: false }` in the rendered head, and `/apply` deliberately absent from the robots disallow list (plan 66-03) so the crawler can actually read that tag. |
| T-66-11 | Information Disclosure | owner contact details published to a link holder | mitigate | The listing summary renders owner display name only; zero occurrences of owner email/phone identifiers, gated by grep (UI-20). |
| T-66-38 | Information Disclosure | a revoked link still serving a cached form | mitigate | `force-dynamic` on the page and `cache: "no-store"` on the context fetch. Without both, Next.js can serve a stale valid render after revocation. |
| T-66-39 | Tampering | client-side state on a shared device | mitigate | The page holds no state at all — Server Component, no hooks. The no-persistence invariant for the form itself is plan 66-12's. |
| T-66-SC | Tampering | package installs | mitigate | Zero packages. Every primitive (`Card`, `Alert`, lucide icons) already exists in `src/components/ui/`. |
</threat_model>
