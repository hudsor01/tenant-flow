### Overflow fix (plan amendment ac364d07d)

At 390 the PLAN_BASE skeleton already overflowed: 10px in the harness and 26px live (`p-4` page padding). What actually blocks shrinking (measured with per-skeleton rects):
- The action-bar inner row is a flex item with `min-width: auto`, so its minimum is its min-content: `w-64` 256 + gap 16 + `w-32` 128 = 400px. The Skeletons themselves do shrink: before the fix, the sibling `w-36` was already squeezed to 0px wide. So Skeleton's base classes (`animate-pulse bg-muted rounded-md`) are not the blocker.
- The header `w-96` sits in a column flex. Its fixed 384px width does not shrink in the cross axis: live it measured 384px inside the 358px content box.

The fix:
- Action-bar row: `flex gap-(--layout-gap-items)` → `flex min-w-0 gap-(--layout-gap-items)`. This is not a Skeleton string.
- The only changed Skeleton string: `<Skeleton className="h-4 w-96"` → `<Skeleton className="h-4 w-96 max-w-full"`. The other 14 `<Skeleton className` strings are byte-identical; the `<Skeleton` count is 15 (37 rendered).

Result, from `w2/vd-12/overflow-fix-geometry.json`, which compares pre-fix B10 with the fixed tree:
- **1280:** all 37 skeleton rects (left, top, width, height relative to the loading root) are identical in harness and live, both themes.
- **390 harness:** 3 rects change. `w-64` 256 → 180.52, `w-32` 128 → 90.25, and `w-36` 0 → 103.23 (no longer collapsed).
- **390 live:** 4 rects change. `w-96` 384 → 358, `w-64` → 164.83, `w-32` → 82.41, `w-36` 0 → 94.77.
- horizontalOverflow is 0 everywhere.

The 1280 reference is the pre-fix B10 tree. PLAN_BASE cannot be the reference, because its look differs on purpose (dashboard.css).

The probe also needed a live-mode fix. As written, the plan's predicate held the `next-router-prefetch` `/_tree` request too. The router then never committed the navigation (URL stayed `/dashboard`), so every capture was `boundary-not-observed`. Now prefetches pass, and the probe waits for network idle plus 1.5s before the DOM click. No check was relaxed.

PNGs (git-ignored, never staged) are in `.planning/tailwind-shadcn/audit/screens/w2-vd-12/{owner-loading-pre,owner-loading-b10,owner-loading-live}/`. Their sha256 values are in `w2/vd-12/png-sha256.json` (12 files). The live PNGs show production owner data.
