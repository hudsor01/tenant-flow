## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] ChartConfig key pattern could not meet the plan's own fixture behaviors**
- **Found during:** Task 2
- **Issue:** The specified pattern `^\s*["']?([A-Za-z_$][\w$-]*)["']?\s*:\s*\{` (multiline) matches only keys at the start of a line. The plan's one-line fixtures (`const c = { revenue: { label: "R" } } satisfies ChartConfig;`, `{ tok: …, extra: … }`) would derive no key.
- **Fix:** `(?:^|[{,])\s*["']?([A-Za-z_$][\w$-]*)["']?\s*:\s*\{` (gm). Multi-line real configs derive the same keys (27).
- **Commit:** `1a7582d8f`

**2. [Rule 2 - Missing functionality] G7 reads the `-(--name)` class shorthand in sources**
- **Found during:** Task 2
- **Issue:** The behavior "a source text `text-(--font-body)` yields `--font-body `" cannot pass with a `var(`-only scan, because the shorthand has no `var(`. Without the shorthand, a source-level reference in that form is visible only through the compiled CSS.
- **Fix:** `G7_SHORTHAND_REFERENCE` (`-(` + optional type hint + name + `)`), merged with the var() refs in `g7References`. The real tree gains no violation from it.
- **Commit:** `1a7582d8f`

**3. [Rule 1 - Bug] Interpolated names**
- **Issue:** The specified `var\(\s*(--[A-Za-z0-9_-]*[A-Za-z0-9_])` backtracks on `var(--color-${k})` and reads the truncated `--color`.
- **Fix:** Capture the name run greedily, plus the next character, and skip the match when the name ends in `-` or is followed by `$`. A fixture control covers it.
- **Commit:** `1a7582d8f`

**4. [Rule 1 - Test bug] Fixture `checked` counts**
- **Issue:** An empty fixture build already references 2 theme-namespace variables (preflight), so absolute `checked` values (1, 0) were wrong.
- **Fix:** Those assertions compare against `emptyBuildChecked()` (+1 for the declared-token fixture). Violation assertions are unchanged.
- **Commit:** `1a7582d8f`

**5. Runner entry reuses `ctx.engine.compiledCss`**
- The plan's sketch calls `loadProjectTailwindEngine()` inside the G7 entry. The runner's `ctx.engine` is the same build (`loadTailwindEngine` with root's globals.css, base `<root>/src/app`, from `<root>/src/app/globals.css`, which is exactly what `loadProjectTailwindEngine` does with `REPO_ROOT` bound to root), so the entry reuses it instead of compiling twice.
