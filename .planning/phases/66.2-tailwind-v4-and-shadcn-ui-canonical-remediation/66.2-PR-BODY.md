### CP-4 layout follow-up (owner-approved)

The 66.2-38 review captures showed three dashboard layout defects. The owner chose CP-4 "Keep + fix layout (Recommended)", then replied "fix everything and put it in this pr". Measured on production builds of the branch and of `754c91802` (`.planning/tailwind-shadcn/audit/cp4-followup/`, `bun cmp.js m-head.json m-pre.json` identical on all 10 pairs at equal content widths), all three predate this phase; wave 6 only made the KPI wrap reachable at 1024 and 1280 collapsed. Fixed on this branch (`deferred-items.md`):

- KPI values wrap (`efb0a6fb9`): each tile's label and value share one wrapping row and the value is `whitespace-nowrap`; every value is one 32px line in all 12 width/state cells.

- Dock over the occupancy donut, 72x66 at 1024x800 (`1a7eecd2a`): `--dock-height`, `--dock-offset` and `--dock-clearance` (90px) in `:root`; `<main>` reserves `lg:pb-(--dock-clearance)` (was `lg:pb-28`) and the root gets `scroll-padding-bottom` while the dock is mounted; dock geometry unchanged.
- Spec pins (`9393102aa`): four new owner-axe tests in `app-shell-sidebar.spec.ts` failed on the pre-fix source and pass after; the unit assertions failed 7 of 103 before and pass after; owner-axe 64 passed, 0 failed.
- `4eeef2029` declares the KPI grid container with the `@container/kpi-bento` utility instead of a static inline style (CLAUDE.md rule 5).
