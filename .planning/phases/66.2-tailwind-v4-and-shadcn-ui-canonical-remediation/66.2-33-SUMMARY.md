## D-47 focus return

`SidebarSheetFocusReturn` keeps `openRef`/`mobileRef`, updates them in one `useEffect` with deps `[openMobile, isMobile]`, and in its cleanup (deps `[triggerRef]`) calls `setTimeout(() => triggerRef.current?.focus(), 0)` when `mobileRef.current && !openRef.current`. **It stayed `useEffect`.** No move to `useLayoutEffect` was needed. Refs are never assigned during render.

I mutation-checked the guards to prove the tests depend on them (each mutation was run and then restored byte-for-byte):
- With the `setTimeout` focus removed, 6 tests fail: Escape, close button, nav item, logo, palette selection, and StrictMode Escape.
- With the `!openRef.current` guard removed, the StrictMode test fails through its trigger focus-event count. Radix's focus trap would otherwise pull a stolen focus straight back into the sheet, so `activeElement` alone cannot show the steal.
- With the `mobileRef.current` guard removed, the new "does not focus the trigger when the first render switches into sheet mode" test fails.
