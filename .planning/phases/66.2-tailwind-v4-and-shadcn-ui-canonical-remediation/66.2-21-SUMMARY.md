**VD-18 geometry (upstream parity).** Upstream new-york-v4's CommandDialog has the identical 0.5px geometry. Its wrapper is `flex h-9 items-center gap-2 border-b px-3`; the dialog's `**:data-[slot=command-input-wrapper]:h-12` raises it to a 48px border box with a 1px `border-b`, and `[&_[cmdk-input]]:h-12` makes the input 48px. Centred in the 47px content box, the input sits 0.5px above the wrapper's top edge, which is less than the 1px border. Raw rects (light and dark): wrapper top 386 / bottom 434; input top 385.5 / bottom 433.5. Task 3's first run used the original strict definition (`i.top < w.top || i.bottom > w.bottom`), measured `true`, and I stopped before committing. The coordinator then redefined the field (eb47da6c6): `inputOverflowsWrapper = inputOverflowPx > wrapperBorderBottomPx`.
