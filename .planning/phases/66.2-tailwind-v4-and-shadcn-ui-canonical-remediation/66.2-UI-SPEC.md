# Phase 66.2 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**The contract in one sentence.** This phase remediates and canonicalizes; it does not redesign. In both themes and at every viewport, every surface renders exactly as it does on `main` @ `754c91802`, except the deltas registered in §Intended Visual Deltas. Any other difference in the screenshot matrix or in a computed-value probe is a defect.

Rules that apply to every section:

1. **The authority is the computed value in Chromium (Playwright), never class presence.** The Phase 65/66 defects shipped with every class present (RESEARCH P5, N2). Class strings below are the prescribed means; the computed values are the contract.
2. **No new colors, fonts, type sizes, weights, routes or navigation entries** (CONTEXT §domain, D-40). Every color is an existing `globals.css` token. No hex, `rgb()`, named color or one-off cubic-bezier enters code (PROJECT.md §Constraints). The `rgb(...)` values below are measured probe readings, never values to write.
3. **Owner judgments are decided and recorded, not left open.** Each ships its default and has a ready fallback (§Review Checkpoints CP-1..CP-5).

**Inputs.** CONTEXT D-01..D-52 (locked); the CLAIMS-LEDGER (its corrected statements override the raw reports); RESEARCH (H1–H12, N1–N21, wave tables); PLAN.md §4.6–§4.8; `sidebar-migration-design.md` D1–D11, V1–V12 and its B1–B20 record of today's behavior; the capability comparison and its critique (the critique wins); `components.json`; `globals.css` at the baseline; a live registry re-fetch on 2026-10-25 at 19:54 UTC. Every class prescribed here was compiled against the worktree's real `globals.css` with Tailwind 4.3.3. Each one prescribed for a first-party call site also passed `canonicalizeCandidates` (`rem: 16`) unchanged, which is the G8 check. Strings prescribed for vendored `src/components/ui/**` files follow upstream verbatim; they are G8-exempt (PLAN decision 6) and were checked to compile. Every contrast ratio was computed from the oklch token values with WCAG 2.x luminance. Scripts and outputs are in `/private/tmp/claude-501/-Users-richard-Developer-tenant-flow/992b9ba7-e5fa-43c5-b8cf-059bace7ca90/scratchpad/ui-spec-66.2/`.

## Spacing Scale

Base unit `--spacing: 0.25rem` (4px). Declared values are multiples of 4 except the exceptions listed below.

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| xs | 4px | sub-menu padding-block (`py-1`); loading-skeleton header padding |
| sm | 8px | sidebar content padding-block (`py-2`), footer bottom padding, loading-skeleton header gap |
| sm+ | 12px | sidebar row padding-inline and icon-to-label gap (`px-3`, `gap-3`); sidebar content and footer padding-inline |
| md | 16px | logo-row padding-inline (`px-4`); space below the section divider; footer top padding |
| lg | 24px | space above the Analytics/Reports divider (`mt-6`); loading-skeleton card gap |
| xl | 32px | sub-menu indent (`ml-8`); loading-skeleton vertical rhythm |
| 2xl | 48px | Cmd+K search row height |
| 3xl | 64px | unchanged page-level spacing (`section-spacing`) |

Component dimensions, all on the 4px grid: menu row 40px (`h-10`), sub row 36px (`h-9`), touch minimum 44px (`--touch-target-min: 2.75rem`), header and logo row 56px (`h-14`), OTP slot 44×56, desktop rail 224px (`--sidebar-width: 14rem`), mobile sheet 288px (`--sidebar-width-mobile: 18rem`), icons 16px and 20px.

Exceptions. All of them are existing geometry the phase preserves; none is new:
- 2px between sidebar rows (`gap-0.5`; today `space-y-0.5`).
- 10px between OTP slots (`gap-2.5`, authored in `3ede630bb` and already rendering).
- 18.4px Switch track height (`h-[1.15rem]`, component-owned; the R5 target).
- 37px tab-trigger height below 48rem (component-owned; D-08 excludes `role=tab` from the touch-target rule).
- 6px and 12px BlurFade entrance offsets (motion distances from the authored `yOffset`, not layout).

**Weights.** The new and vendored UI uses two: 400 and 500. The wordmark keeps its existing `font-semibold`. That is 600 declared and 700 rendered, because Roboto loads static 300/400/500/700 files. It is a preserved lockup, not a new weight. The weight system is frozen: D-10 locks it, and the variable-Roboto switch is deferred as D-A.

**Families (B3 / D-09).** The font variable classes move from `<body>` to `<html>` in both `src/app/layout.tsx` and `src/app/global-error.tsx`.

| Family | Theme token (`@theme inline`) | Resolves to | Fallback stack |
|--------|-------------------------------|-------------|----------------|
| Sans | `--font-sans` | `var(--font-roboto)` | `system-ui, -apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, sans-serif` |
| Display | `--font-display` (removed in 66.2-13, owner decision 2026-10-31) | — | — |
| Mono | `--font-mono` | `var(--font-geist-mono)` | `ui-monospace, "SF Mono", "Cascadia Code", monospace` |

`<code>` and `<pre>` lose their hard-coded system-mono `font-family`, so preflight's mono stack (Geist Mono) applies. Their size, padding and background are unchanged. No other size or line-height changes anywhere: the display, title, caption and stat scales are untouched. The 18 `text-caption` call sites keep 11px and the same muted color. B8 only makes the color explicit (`text-caption text-muted-foreground`), and the computed value is identical.

## Component Contracts (UIC-01, UIC-07)

### Touch-target rule (B2, D-08, wave 1)

The rule lives in `@layer base` at zero specificity, below 48rem only, and sets no padding. Any utility on the control overrides it because the cascade orders `@layer utilities` after `@layer base`, and layer order is compared before specificity; the `:where()` wrappers matter only against other `@layer base` rules (66.2-39 F5). This is the pre-validated CSS from PLAN §4.8; Biome reflows it.

```css
@layer base {
	@media (width < 48rem) {
		:where(button:not([role="switch"], [role="checkbox"], [role="radio"], [role="tab"]), [role="button"]) {
			min-height: var(--touch-target-min);
			min-width: var(--touch-target-min);
		}
		:where(input:not([type="checkbox"], [type="radio"], [type="range"], [type="file"], [type="hidden"]), select, textarea) {
			min-height: var(--touch-target-min);
		}
	}
}
```

The unlayered `@media (max-width: 768px)` block, and its `.btn`, `.form-input` and `.mobile-*` selectors, are deleted.
