## Summary

This phase is a measured cleanup of a Tailwind v4 + shadcn/ui styling layer, delivered as six ordered waves in one PR. The B/X findings and the 34 component/sidebar claims are already adjudicated (ledger). This research answers the planning-specific questions: how the waves overlap on the same files and where ordering breaks a guard or a test, exactly how each guard can be built and proven red on the baseline, what the wave-3 token restructure touches, how to canonicalize classes mechanically, and what the vendored sidebar needs.

I prototyped all eight guards against the current tree. Each one fails on the baseline: G1 1, G2 11, G3 2, G4 6, G5 44, G6 1, G7 8 and G8 97 violations. The whole suite runs in 2.2 s in plain Node. Under the repo's Vitest `threads` pool it takes 3.2 s; the compile, the scan of 914 `src/` files and the canonicalization of 1,924 candidates all fit in that. I also dry-ran a wave-4 codemod. It made 168 in-place edits across the 53 first-party files with no position mismatch, once I accounted for Oxide returning UTF-16 indices. The canonical new-york-v4 `sidebar.tsx` (sha256 `2ba1a9b9…`, unchanged in the live registry today) typechecks with **zero errors** under the repo's strict tsconfig. It needs only its imports rewritten to `#components/ui/*`, `#lib/utils` and a local `use-mobile`.

Research also surfaced several hazards that the ledger and PLAN did not anticipate, and that the planner must design around:
- **(N2)** `src/lib/data-table.ts` applies `background: var(--background)` to every data-table cell. Today `--background` is undefined, so cells are transparent (measured). Wave 3 *defines* `--background`, so every cell turns opaque and hides TableRow's `hover:bg-muted/50` and `data-[state=selected]:bg-muted`. The token snapshot cannot catch this.
- **(N3)** The ledger's BorderBeam fix, `--animate-border-beam` in non-inline `@theme`, does **not** animate (measured `animation-name: none`). It must go in `@theme inline` (measured running). It would also fail G2.
- **(N4)** After B2, the `/applications` status strip no longer overflows at 375px (308 px natural width vs a 327 px box). That breaks the CI-gating owner-axe E-22 positive control.
- **(N6)** A `// @vitest-environment node` test file crashes at setup (`document is not defined`), because `unit-setup.ts` touches the DOM unconditionally.
- **(N7, N8)** Several guards depend on later-wave fixes: G2 needs the brand sidebar block (D-21) deleted, G6 needs the bogus `@source` (B9) deleted, and G7 needs LoadingSpinner (C12d) fixed. Lefthook blocks red commits, so each guard must land with the fix it depends on.

**Primary recommendation:** Plan each guard as a pure function over the real CSS. Give it a positive assertion on `globals.css` plus a minimal fixture negative control, and land it in the same commit as its fix. Pull three tiny zero-impact fixes forward so each guard can land green with no allow-list exceptions: the bogus `@source` (to wave 1), the brand sidebar `@theme` block (to wave 1) and LoadingSpinner's dangling `--font-*` vars (to wave 2). Then handle the four measured hazards (data-table `--background`, BorderBeam `@theme inline`, E-22, test environment) as explicit plan tasks.

- **Zero-tolerance rules:** (1) no `any` (Biome `noExplicitAny`); (2) no barrel files / re-exports. `src/lib/fonts.ts` may *define* fonts but must not `export { GeistMono } from "geist/font/mono"` (see N19); (3) no duplicate types, so check `src/types/*` first (e.g. `BlurFadeProps` lives at `src/types/frontend.ts:114`); (4) no commented-out code; (5) no inline styles except runtime-computed values. Canonical sidebar's static `style={{"--sidebar-width": …}}` and upstream Sonner's static `style` map violate this (V2 / N20); (6) no PG enums (n/a); (7) no emojis; (8) no `as unknown as`; (9) no string-literal query keys (n/a); (10) `lucide-react` only (canonical sidebar uses `PanelLeftIcon` ✓).
- **Testing:** never run bare `vitest`, `bun run test`, `bun run test:ci` or `bun test`. Unit: `bun run test:unit -- <file> -t "<name>"`, and never add `--run`. Coverage thresholds are a ratchet at the `vitest.config.ts` ROOT: statements 64, branches 56, functions 63, lines 66. Never move `coverage` into `projects[]`. Use `vi.hoisted()` for mock vars, and use `.rejects.toMatchObject` rather than `.rejects.toThrow("…")`. Never leave `.skip`. Don't name a test `*.component.test.tsx`.
- **Unit tests run in lefthook pre-commit and, since #1041 (`80d282a5a`, after this research's base `754c91802`), in CI `checks` on every pull request** (`bun run test:unit -- --coverage`), Dependabot's included. `checks` is `pull_request`-only, so a direct push to `main` runs no unit test.
- **E2E:** CI runs `smoke`, `public` and `owner-axe` against PRODUCTION Supabase. Authenticated specs use `loginAsOwner` and must join the `owner-axe` allowlist. Gate on hydration, not visibility. Upload no artifacts and no traces.
- **Frontend conventions:**
  - Status TEXT uses `-text` companions, and muted text uses `text-muted-foreground` (never bare `text-muted`).
  - Use `bg-background`, never `bg-white`. No gradient text.
  - Anything importing `recharts` loads via `next/dynamic`.
  - `design-token-drift.test.ts` fails on hex, `rgb()`, `bg-white` and non-zero `NNNms` literals in `src/app` and `src/components`. The `modernColor` rule applies to the `api/og/` satori routes.
  - Icon-only buttons need `aria-label`, and label-in-name (WCAG 2.5.3) applies.
  - Exactly one `<main id="main-content">` per shell. Use the shadcn `Switch` for toggles.
- **Next 16:** read `node_modules/next/dist/docs/` first. `src/proxy.ts` replaces middleware. Nonce-CSP routes (private prefixes, `/login`, `/auth/*`) must render dynamically. Changing `ThemeProvider` props means recomputing `THEME_NO_FLASH_SCRIPT_HASH`.
- **Toolchain:** bun 1.3.14; Biome (tabs, double quotes, import order) via `bun run lint` / `lint:fix`; TypeScript 7 (`tsc` 7.0.2, no classic compiler API). `bun add` changes must commit `bun.lock`.
- **Security:** run an Aikido full scan on new or modified first-party code and fix-and-rescan until clean. If the Aikido MCP server is unavailable, tell the user.
- **Git:** conventional commits with a lowercase subject, ending with `[hudsor01]`. Never `--no-verify`. Never commit `CLAUDE.md` or `AGENTS.md`. Never push to main. The perfect-PR gate is two consecutive zero-finding cycles on the frozen state.
- **Stale / do not follow:** `docs/*`, tracked `memory/`, `supabase/SCHEMA.md` and the rest of that list.

### Pattern 1: Guards as pure functions + fixture negative controls (lefthook-compatible TDD)
**What:** Each guard is `checkGx(input) → Violation[]`. The test asserts `checkGx(real) === []` (positive) and `checkGx(fixture) .length > 0` (negative control reproducing the baseline defect class). As one-time evidence, the plan's SUMMARY also runs the same function against `git show 754c91802:src/app/globals.css`.
**Why:** lefthook runs the whole unit suite on every commit, and `--no-verify` is forbidden, so a red guard can never be committed alone. The fixture control proves permanently that the guard *can* fail, which is the property D-17 asks for, and the git-baseline run proves it failed on the real baseline.
**Example fixtures (measured to trip the prototype):** G1 `@theme{--color-x: oklch(95.46% 3.51 246.58)}`; G2 `@theme{--font-sans: var(--font-sans), x}`; G3 `@utility text-caption{font-size:1px}`; G4 `@theme{--color-q: oklch(0 0 0 / 50%)}` with no dark value; G5 a key absent from the config; G6 `@source "..*.{ts,tsx}"`; G7 `var(--spacing-99)`; G8 `flex-shrink-0`.

### Pattern 2: Value-parity proofs by computed value, not class text
The candidate-css text diff is necessary but not sufficient. Deleting the spacing scale changes the rule text of **469 / 1924** candidates while every value stays equivalent (measured). Wave 3 changes nearly every color utility's text (`var(--color-x)` → `var(--x)`, and opacity rules gain an `@supports (color-mix)` block with a full-opacity fallback). The authority for "unchanged" is a Chromium computed value: render-check's token snapshot plus probes. Raw text diffs feed a normalizer that classifies every hunk.

### Pattern 3: One shared engine state per test file
Compile, scan and load the design system once (`beforeAll` or a module-level promise) and share them across G1–G8. Measured cost: compile+scan 120–133 ms, design system 16–44 ms, G8 canonicalize loop ~1.8 s (1,441 first-party valid candidates), G6 ~136 ms.

### Anti-Patterns to Avoid
- **Regex copies of CSS in tests** (X1, X6): always read the real file through the engine.
- **Class-presence assertions for cascade properties** (Phase 65/66 lesson): prove computed values (`base-rule-cascade.ts`, Playwright).
- **Applying `canonicalizeCandidates` after deleting `--spacing-N`:** it then suggests `X-(--spacing-N)`, which preserves a dangling var (N10).
- **Putting a `var()`-bearing token in non-inline `@theme`:** it is resolved at `:root` (B3/B11/N3 class).
- **Static `style={}`:** canonical sidebar widths and upstream Sonner's map must become CSS or className.

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| Class canonicalization / M10 | regex rewrites of class strings | `ds.canonicalizeCandidates([c], { rem: 16 })` + Oxide `getCandidatesWithPositions` | Variant, arbitrary-value and theme equivalence is engine knowledge |

## Common Pitfalls

### P1: B2 breaks the CI-gating E-22 positive control (N4)
**What goes wrong:** `applications.spec.ts` E-22 asserts `strip.scrollWidth > strip.clientWidth` at 375px. Measured in a harness with the real TabsList/TabsTrigger classes, the 5-label strip's natural width is 348 px today because the unlayered rule forces 12px padding and a 44px min-width. After B2 it is 308 px (8px padding, tabs excluded; trigger height 44→37 px). In the real page the box is 327 px at 375px, so it no longer overflows and the positive control fails. At 320px (box 272) it still overflows.
**How to avoid:** in W1, re-measure in the real page and re-scope E-22: positive control at 320px, or assert "fits without clipping OR scrolls within the strip". Update its comment (it cites `globals.css:1536`).
**Warning sign:** owner-axe red on the first post-B2 CI run.

`render-check.mjs` takes fonts from `layout.tsx` and pairs from hard-coded classes. After B3/B4 it would report "failing" fonts and measure deleted classes. Update it before W1 lands, and use a fixed token list.

### use-mobile (D-33)

```ts
"use client";
import { useEffect, useState } from "react";
const MOBILE_QUERY = "(width < 64rem)"; // exact complement of Tailwind `lg`
export function useIsMobile() {
	const [isMobile, setIsMobile] = useState<boolean | undefined>(undefined);
	useEffect(() => {
		const mql = window.matchMedia(MOBILE_QUERY);
		const onChange = () => setIsMobile(mql.matches);
		mql.addEventListener("change", onChange);
		setIsMobile(mql.matches);
		return () => mql.removeEventListener("change", onChange);
	}, []);
	return !!isMobile;
}
```

```js
	.map(({ candidate, position }) => ({ at: position, from: candidate, to: ds.canonicalizeCandidates([candidate], { rem: 16 })[0] }))

	.sort((a, b) => b.at - a.at);
for (const e of edits) src = src.slice(0, e.at) + e.to + src.slice(e.at + e.from.length);
```
