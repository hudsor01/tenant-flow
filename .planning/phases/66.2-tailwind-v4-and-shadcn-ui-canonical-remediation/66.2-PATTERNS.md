## Read first: 10 mapping findings that RESEARCH.md does not state

1. **The list harness reads only the LIST's own classes** (`src/test/utils/base-rule-cascade.ts:126-143`, `:179-183`). `computeListCascade(list)` emits rules for `utilityRules(list)`, which covers the list's classes, including the `[&>li]:` child variant. It emits nothing for classes on the `<li>` itself. A `mb-0` on `SidebarMenuItem`'s own `<li>` therefore produces no rule, the harness reports `firstChildMarginBottom: "4px"`, and D-49 cannot be proven as written. There are two ways out:
   - (a) put `[&>li]:mb-0` on `SidebarMenu`/`SidebarMenuSub`. This is the repo convention: "Tailwind's arbitrary child variant as written on every list in this repo", `base-rule-cascade.ts:69-70`.
   - (b) extend the harness to also apply `utilityRules(list.firstElementChild)`.

   The harness also maps only `pl-0`/`mt-0`/`mb-0` (`:63-67`). Canonical `SidebarMenuSub`'s `px-2.5 py-0.5` are logical properties, so they need the E2E computed check.
2. **A cookie writer already exists.** `secureCookie.set` (`src/lib/dom-utils.ts:18-59`) writes `name=value; path=/; max-age=N; SameSite=Lax`, plus `Secure` when the page is on https. `src/lib/theme-utils.ts:35-41` already uses it for a UI-preference cookie. RESEARCH's `serializeSidebarCookie()` would duplicate it.
3. **`setupErrorMonitoring` IGNORES hydration errors.** It lives in `tests/e2e/tests/helpers/navigation-helpers.ts`, and its ignore list at `:103-105` contains `"Hydration failed"` and `"Text content does not match"`. The new spec's no-hydration-error assertion needs its own `page.on("console")` collector.
4. **Geometry reads are mechanically banned in specs.** `tests/e2e/lib/__tests__/measure-is-the-only-geometry-read.test.ts` runs in the unit project, so in lefthook. It fails any `boundingBox()` or `getBoundingClientRect()` outside `polledRead(...)` plus its `SANCTIONED_POLLED_READS` allowlist (`:92-97`). Use `boxOf`/`widthOf`/`polledRead` (`tests/e2e/lib/measure.ts:104,161,248`) or `getComputedStyle`/`scrollWidth`.
5. **`main-nav.test.tsx:152-160` keys sections on `button[aria-controls^="nav-section-"]`.** Radix `CollapsibleTrigger` sets `aria-controls` to its own generated content id, so this selector matches nothing after W6. Re-key it on `[data-slot="collapsible-trigger"]` (W5 adds data-slots to `collapsible.tsx`, C14) or on role plus name. Never pass a custom `id` to `CollapsibleContent`: Radix spreads props after its `id`, which desyncs `aria-controls`.
6. **G8 is live from W4 onward, so new classes must already be canonical.** It runs on every commit for every non-`src/components/ui/**` file. So every class written in W5 outside `ui/` and in W6 (shell files, dock, tour, layout) must already be canonical. Check new arbitrary classes, such as the dock's `lg:left-[calc(50%+var(--sidebar-width)/2)]`, with `ds.canonicalizeCandidates([c], { rem: 16 })` before committing. The sidebar header comment (V1–V12) and the comments in `fonts.ts`, `sidebar-state.ts` and `utils.ts` are all scanned.

Every shell test renders `<AppShell>` directly, so keep `AppShell` as the exported entry and put the hook users in an inner component.

The B8 rewrite is safe before B7 only because all 18 sites are raw DOM `className` strings, not `cn()` merges. Each grep hit is a `<p>`, `<span>` or `<div>`, so plan 06-before-07 holds.
