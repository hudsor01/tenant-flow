## Deviations from Plan

### Auto-fixed / harness

**1. [Rule 3 - Blocking] `bun run test:e2e` did not deliver the worktree credentials to Playwright**
- **Found during:** Task 2 step 4
- **Issue:** the first two local runs skipped E-22 with the suite's own reason, `no application fixture: E2E_OWNER_PASSWORD / Supabase env not set`. A dummy-directory test (scratch `.env.local` holding `FOO_PROBE=loaded`) showed why. In bun 1.3.14, `bun run <script>` gives the script's child `undefined`, while `bun <file>` loads the cwd env files (`loaded`). So the plan's premise that `bun run <script>` loads the file into the tool it runs does not hold for child processes.
- **Fix:** a scratch launcher (`scratchpad/exec/bun-env-launch.mjs`, run as `bun <launcher> node_modules/.bin/playwright test …` from the worktree root). Bun loads the env files into the launcher, which spawns Playwright on Node with the inherited env. `.env.local` was never opened, read, listed or sourced, and no value or name was printed. Gate: `test -f`. Both local runs (E-22, E-2/E-3) used it.
- **Impact on later plans:** every credential-consuming `bun run test:e2e` in this worktree needs the same launcher, or it skips silently. 66.2-10's owner-axe step should use it.

**2. [Measurement] The real-page strip container is 295/240, not 327/272**
- **Found during:** Task 2 step 4
- **Issue:** the plan's interfaces (from RESEARCH) give the real-page box as 327px at 375 and 272px at 320. The local real-page run measured 295 and 240, so the ~319px strip scrolls at 375 as well. The plan's JSDoc sentence "fits the 327px box at 375" would be false.
- **Action:** the assertions are exactly as specified (fit-or-scroll at 375, overflow control at 320). The JSDoc states the measured truth instead: natural width near 320px, fit at 375 depends on the container, 240px measured at 320. The scratch probe used the plan's 327/272 boxes, as Step 1 specifies.

**3. [Strengthening] D-08 controls also run on compiled fixtures**
- The negative and layering controls assert on the raw string constant, as specified. They also assert on the same text compiled through `loadFixtureEngine` (2 and 0 violations), which proves the walk handles real emitted CSS, preflight's layered `button, input…` rules included. The positive structure test walks `parseCss(engine.compiledCss)` (the engine's own postcss helper), so there is no second compile path.

**4. [Measurement] css-parity classifies the textarea keys as intended `changed`**
- `min-h-24!` exists only pre and `min-h-24` only post. css-parity's intended matcher absorbs both, so `lists.added`/`lists.removed` are empty and `check-parity-06.mjs` passes trivially on them. To keep the check non-vacuous, the script also traces both intended keys to `+` and `-` diff lines.

**5. [Probe scope] /pricing CTAs do not carry `data-slot="button"`, and /contact's first text input is an `InputGroupInput`**
- The selector `main button[data-slot="button"]` matched nothing, so the probe was widened to every visible `button`, `a[data-slot=button]` and `[role=button]`. On /contact, the first text input (`#name`) is an `InputGroupInput` whose own padding is `4px 12px 4px 8px`. The plain `Input` the acceptance row describes (`#company`) measures `4px 12px`. Both are 44px, and neither is padded 12px all round.

**6. [Harness] Playwright reporter**
- Local runs used `--reporter=json` with `PLAYWRIGHT_JSON_OUTPUT_NAME` set to the scratch dir, and `PLAYWRIGHT_HTML_OPEN=never`, so the local HTML reporter could not serve-and-wait on failure. No artifact was uploaded, traces stayed off, and nothing under playwright-report/ or test-results/ was staged (`git status` was clean before every commit).
