## Task 1 Step 0: shipped selectors versus the plan's interfaces

Every selector in the plan's "Canonical Sidebar DOM" exists in the shipped `src/components/ui/sidebar.tsx` and shell files. There is one composition fact the plan does not state: `Collapsible asChild` and `CollapsibleTrigger asChild` hand their own `data-slot` to the child. So:
- the section `li`s carry `data-slot="collapsible"`, not `sidebar-menu-item`;
- the toggles carry `collapsible-trigger` (PATTERNS #5, as the plan expects).

`[data-slot="sidebar-menu-item"]` therefore matches 9 items (7 core and 2 footer). Test A also asserts all 11 `[data-slot="sidebar-menu"] > li` items.

- **`inert`:** `useCollapsedInert()` puts it on `[data-slot="sidebar-header"]`, `[data-slot="sidebar-content"]` and `[data-slot="sidebar-footer"]` when `!isMobile && state === "collapsed"`. It is never on the container.
- **Rail versus inert:** `SidebarRail` is a child of `<Sidebar>` (the container), outside every inert subtree. Test D proves it by clicking the rail from the collapsed state, which expands the sidebar.
- **Close button:** the visible control is the `aria-label="Close navigation menu"` app button in `app-shell-sidebar.tsx`. The SheetContent keeps `[&>button]:hidden`.
- **Result:** no difference from the reconciled 66.2-32/33 contract, so no `src/` fix was needed.
- **Dock hook:** 66.2-35 added no stable hook, so this plan added `data-testid="quick-actions-dock"`.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Spec bug] `--color-sidebar-accent` / `--color-sidebar-ring` are not resolvable custom properties**
- **Found during:** Task 2, Test C (first run).
- **Issue:** `globals.css` declares the `--color-sidebar-*` names in `@theme inline`, so Tailwind inlines them as `var(--sidebar-*)` and emits no custom property. `var(--color-sidebar-accent)` on the probe span was therefore invalid at computed time, and the span inherited the body text color. Expected `lab(7.2 …)` (text), received `lab(93.06 …)` (the real accent).
- **Fix:** `resolveColor` resolves `--sidebar-accent` and `--sidebar-ring`, the properties the `--color-*` names alias. It now throws when a token is not declared on `:root`, so this failure mode cannot recur silently. The contract (hover equals the sidebar accent, the ring contains the sidebar ring color) is unchanged.
- **Commit:** `df801fe95`

**2. [Rule 1 - Spec bug] floating-ui first renders the tour step at `translate(0px, 0px)`**
- **Found during:** Task 3, T1.
- **Issue:** the step box read y 0 before `computePosition` resolved. A computed-transform gate does not help, because floating-ui applies `translate(0px, 0px)` before placement too.
- **Fix:** `placedStepBox` polls until two consecutive reads (at least 100 ms apart) return the same box. That is a layout-settling gate, independent of where the step lands.
- **Commit:** `6989ce5ac`

**3. [Rule 3 - Blocking] Tour step 1 footer below the fold at 1280×720 with the rail expanded**
- **Found during:** Task 3, T4.
- **Issue:** Playwright reported "element is outside of the viewport" on step 1's "Next step". The step is `fixed` and its footer renders below y 720.
- **Fix:** `openTourAtStep5` advances with `focus()` + Enter, as a keyboard user would. Step 1 placement is outside wave 6 and is logged in `deferred-items.md`.
- **Commit:** `6989ce5ac`

**4. [Rule 1 - Spec race] Escape layering read before Radix re-rendered the layer stack**
- **Found during:** Task 4 Step 2, the first production-build gate run (M2 at 900 failed). It was then measured as 6 of 10 failures with `--repeat-each`.
- **Issue:** Radix DismissableLayer 1.2.1 attaches each layer's Escape listener in an effect keyed on whether that layer was highest at its last render. For about a frame after the palette mounts, the sheet still holds the only listener. An Escape sent right after the palette's focus therefore closed the sheet instead. A human cannot press Escape inside that window. A `toBeFocused` gate alone did not close it.
- **Fix:** `waitForLayerStack` waits until Radix restyles both layers for the new stack (palette content `pointer-events: auto`, sheet `none`), then one frame. After the fix: 10/10, then 20/20 and 6/6. The Escape-layering assertion is unchanged.
- **Commit:** `72cd9168b`

**5. [Rule 1 - Spec race] The palette's navigation was replaced by the dashboard's URL write**
- **Found during:** Task 4 Step 2, the second gate run (M2 at 375). Measured in 2 of the 16 production-build runs that reached close path 5.
- **Issue:** after the option click, Playwright logged two navigations to `/dashboard?page=1&perPage=10` (the data tables' nuqs `replace`) and none to /properties.
- **Fix:** close path 5 now waits for the dashboard content and `networkidle` after `page.goto("/dashboard")`. After the fix: 20/20 and 6/6. The navigation assertion is unchanged.
- **Logged:** the product-side race is in `deferred-items.md` (out of wave-6 scope; its cause is not measured).
- **Commit:** `72cd9168b`

**6. [Rule 2 - Safety] `user_tour_progress` answered locally in every authenticated test**
- **Why:** the plan intercepts the table only in the tour tests. The first `loginAsOwner` load happens before `gotoAuthedDashboard` sets the localStorage tour key, so the tour could read, or open and write to, production.
- **Fix:** `fulfillTourProgressAsCompleted` answers GET with a completed row and any write with 201, before `loginAsOwner`. Nothing is forwarded.
- **Commit:** `715382583`

**7. [Rule 1 - Spec determinism] Tab walks start from a prepended `tabindex=-1` node**
- **Issue:** the plan says to focus `document.body` before the walk. Chromium keeps the sequential-focus starting point at the last focused or clicked node (here the trigger, after it collapses the rail). A walk from there would skip the sidebar no matter what, which makes the collapsed-rail check vacuous.
- **Fix:** the walk starts from a throwaway node prepended to `body`, so it begins at the page start as the plan intends. The expanded walk is the positive control.
- **Commit:** `df801fe95`
